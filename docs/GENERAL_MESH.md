# G02: 一般輪郭の適合メッシュ生成

## 仕様と受入範囲

G01の単一・軸接続・直線多角形を対象とする。全頂点と各辺のaxis/PEC/対称タグを
保持し、自己交差の修復、頂点の間引き、狭い隙間の閉鎖はしない。
旧profile系のJSONとメッシュ生成結果を保持する。穴はP03、曲線要素はG03。

生成は初期分割、サイズ制御と品質改善、完成メッシュ検証の段階に分ける。
初期分割は凸な三頂点を取り出し、他の残存頂点を内部にも辺上にも含まない場合だけ
三角形として確定する。これにより直線上のタグ切替点も削除しない。
座標は最大寸法で正規化し、正の向きが数値的に解決できない場合は、対象形状の
特徴寸法確認または検証済み外部meshを案内して失敗する。端面全体からタグを推測しない。

候補三角形は面積/辺長二乗和が最大のものを優先し、同点は輪郭順とする。
これは初期分割の選択規則であり、最小角・最大辺長の保証ではない。
細分化の共有辺は単一の中点を使い、境界子辺は親辺のタグを引き継ぐ設計とする。
全域サイズと境界/角近傍サイズの具体的な入力契約、品質改善方式と停止制限は
測定後に確定する。初期分割だけで自動solveを公開しない。

G02全体の受入には次を必要とする。

- 全境界線分の完全被覆・タグ一致、正面積、接続円板位相、面積と回転体体積。
- 狭い隙間、共線タグ切替、細長い領域について、品質分布・サイズ達成・失敗条件。
- 同じ入力からの再現性、旧JSON/旧計算の回帰、生成時間・要素数・使用メモリ。
- 非円筒の独立参照との周波数・場・RF・表面量の個別収束。小残差だけでは受入しない。
- Case/CLI/保存/GUI経路の生成設定と結果の保持。

## 初期分割の実装・証拠 — 2026-09-08

`contour_mesh.triangulate_contour` は境界頂点だけの N−2 三角形を生成し、既存の
厳密なmesh入力検証を通す。`make_mesh` の一般輪郭自動生成はまだ未対応のまま。
`tests/test_contour_mesh.py` は独立矩形分解の面積/体積、円錐、幅1e-5の経路、
共線の軸/端面頂点と混在タグ、寸法1e-6〜1e6、同一入力の再現性を検証する。
狭い隙間の分割成功を、その三角形のFEM精度や品質保証とは扱わない。
標準検証は `out/validation-g02-initial-20260908/validation.json` がPASS。

## 依存判断（暫定）

この初期分割は向きと包含の計算から独立実装し、既存NumPyのみを使う。
新規依存は採用しない。以下の細分化測定だけでは品質改善・精度を受入できず、Gmsh等の
採用/不採用の最終ADRにはまだならない。G02.Sは進行中、Iは部分実装、Vは未受入。

## タグを保持する細分化と品質測定 — 2026-09-08

内部API `refine_contour(case, mesh, max_edge_m, *, max_triangles=250000,
max_passes=30)` を追加。全辺の最大長を指定し、Caseの既存boundary_max_edge_mと
corner_max_edge_m/corner_radius_mで追加の局所細分を行う。
境界指定は軸を除く全境界、角指定は輪郭の実際の方向転換点（軸端も含む）を中心とする
閉球と交わる全辺が対象。共線タグ切替点は保持するが、角の中心とは扱わない。
サイズ比較の相対余裕は1e-12。正の有限サイズ・正整数の停止上限以外は拒否する。
Case/JSONへの全域サイズ契約と自動solve公開はまだ未完了。

共有辺の中点を一度だけ生成し、短辺分割時には所有要素の最長辺も分割する。
子境界辺には親タグを継承し、毎段階で既存の完全被覆・面積・接続検証を通す。
新規要素数は生成前に上限と比較する。失敗時に途中のメッシュを完成結果として返さない。
既存profile用細分の分割規則を内部再利用した独立の経路で、旧計算経路は変更していない。

`contour_mesh_quality` は最小角、最小/中央値の q=4√3 A/Σ辺長²、最大辺長と
頂点/要素数を返す。これらは幾何測定であり、RF誤差の推定値ではない。
直角二等辺三角形の45度・q=√3/2で測定式を独立検証。
矩形分解の面積/体積、局所サイズ達成、混在タグ長、再現性、停止条件もテストした。

再現コマンド: `OPENBLAS_NUM_THREADS=1 python scripts/measure_contour_mesh.py --out out/mesh-g02-new`
（インストール済み環境で実行し、未使用の出力先を指定）。

## 内部対角辺の組替え — 2026-09-08

`improve_contour_angles(case, mesh, max_sweeps=100)` を追加。内部の隣接2要素について
新しい2三角形の向きが正で、最小角が厳密に改善するときだけ対角辺を交換する。
新対角辺は旧辺より長くせず、角近傍のサイズ制御も検査する。頂点・境界辺・タグは不変。
辺番号順で、1巡内では同じ要素を再編集しない。規定巡回数後にさらに改善候補が残れば
明示失敗し、途中状態を完成結果として返さない。局所改善でありDelaunay保証ではない。
共線/非凸/数値的に不確かな交換は採用しない。

検証は境界/タグと解析幾何モーメント、最大辺長と局所サイズ、最小角の非悪化、
品質中央値の改善、再現性・再適用の固定点。標準186件中184合格・2 skip、
`out/validation-g02-flips-20260908/validation.json` PASS。旧2形状の全mode量/hashは不変。

`scripts/measure_contour_mesh.py` に組替え後の品質と所要時間を追加。
証拠 `out/mesh-g02-flips-20260908/measurements.json` では最大辺0.25 mの場合、
経路幅0.5/0.01/1e-5 mの品質中央値はそれぞれ
0.7111→0.8660 / 0.03462→0.10363 / 0.00003464→0.00010392へ改善。
ただし最小角は全例で細分化後から不変。固定頂点の対角辺交換だけでは狭い経路の
角品質不足を解決できない。次は頂点配置/追加方式と必要要素数を評価する。
製品メッシュ方式・品質受入・依存判断は引き続き未確定。
