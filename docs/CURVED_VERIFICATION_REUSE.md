# 曲線適応実行中の検証済み先祖の再利用

2026-09-09、直前基準07dac27。[前回の費用比較](CURVED_REFINEMENT_EFFICIENCY.md)では
適応側のFEM solve合計約7.35秒に対し、全体約119秒を要した。
先祖水準の再構築・追跡・指標・ピーク・高次積分の重複評価を、実行内だけで削減する。
全体時間には他の処理も含まれるので、この差すべてを一つの処理の費用とはみなさない。

再利用は execute 呼出しごとに作る非公開の状態だけで行う。
既に検証した水準の報告と出所、最後のnative場を保持し、過去全水準の行列は保持しない。
新水準の評価前に、要求の完全一致・実装hash・先祖のパス列・Case/結果JSON/場NPZ/メッシュ/保存プロトコル・完了記録の内容hashを照合する。
変化は再利用の中止とエラーになり、変更後の先祖を黙って正当化しない。
新水準のCase・元メッシュ・幾何・native場/RF・追跡・指標・ピーク・高次積分は従来どおり検証する。
評価後と次の計算計画を作った後にも、元ファイルが変わっていないことを確認する。

状態を更新するのは一連の照合が通った後だけで、報告メタデータは深いコピーを保存する。
エラー時は直前のcheckpointを保持し、次のcheckpointを公開しない。
ファイルの意味が同じでもバイト列が変われば、出所変更として拒否する。
出所確認ではmtimeだけに依存せず、既存のSHA-256・通常ファイル/シンボリックリンク検査を使う。
この契約は、検査と検査の間に一時的に変化して元へ戻されたファイルを監視する仕組みではない。

再開時は保存checkpointの全水準を新たに評価し、保存文書と完全照合した後にだけ再利用する。
この照合で次の計算計画も得るため、同じ先祖を直後にもう一度組み直す必要がなくなる。
保存JSONの内容自体を信頼済みキャッシュとして受理しない。
独立した read/replay は実行内の再利用状態を受け取らず、従来どおり全水準を再検証する。
版1/2/3も、共通の文書照合の意味・出力形式を維持する。

検査条件は、実3水準で水準評価が3回となること、3水準からの1水準再開で評価が計4回となること、
独立再検証が全水準を検証して同じ文書を返すこと、出力された文書の改変を再開前に拒否すること。
新しいsolve後、または新水準の表面評価中に先祖を変えた場合も、次のcheckpointを公開してはならない。
さらに同じ球形対照を再実行し、解析五量・自由度・停止系列が変わらないことを検査する。
これは再検証費用の改善であり、細分方式の一般的な精度・効率の受入を意味しない。
