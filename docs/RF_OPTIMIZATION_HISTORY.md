# 固定局所細分履歴を保つRF制約付き探索

2026-09-14、D03/P2-02の「局所細分履歴」の接続範囲を受入。
探索要求版2で、元の曲線Projectの順序付き細分履歴を保持して半径・軸方向を探索する。
各候補は元Projectから独立に変形し、元履歴の**後ろ**へ全域細分を追加する。
探索アルゴリズム・FEM・物理定数・五量の許容差は変更しない。

## 問題と受入条件

従来版1は履歴付きProjectを拒否していた。要求の版だけを増やしても、
探索器が`curved_refinement_levels`を増やすため、順序付き履歴と競合してCaseが拒否する。
履歴を捨てたり、局所要素番号の前へ全域細分を挿入して解決してはならない。
`baseline-red.log`に版拒否とCaseの競合を再現した2件を保存した。

独立な幾何不変量は、固定参照分割の制限と宣言したアフィン変換が可換であること。
各細分の接続・境界所属・二次座標が対応し、同じ候補の追加細分では
Green境界積分による面積・回転体積が変わらないことを確認する。
実FEMの独立検証には球形の解析五量、長さと規格化エネルギーを変えた
Maxwellのf/RF/場尺度則を使う。小さな代数残差を離散化精度の証拠にしない。

受入条件は、厳密な版/入力、固定した分割の保持、候補ごとの3実FEMと最終の別3実FEM、
個別モード対応・元の五量判定、全保存場からの再開/再生と改変拒否、
CLI・worker・GUIの入力保存/中止再開/対象場/表面評価である。
要求版1と従来の表面評価版1の保存を維持する。

## 要求版2と細分の意味

フィールドは[版1のRF探索](RF_OPTIMIZATION.md)と同じで、`schema_version`を2にする。
全marked段階に有効な`split_pattern`と明示元メッシュが必要。
先に[局所分割の固定](FROZEN_CURVED_REFINEMENT.md)を行い、そのProjectを渡す。
探索開始時に暗黙の固定や元メッシュの作り直しはしない。
一様段階だけの順序付き履歴も利用できる。版1での履歴拒否は維持する。

| 試行 | 元履歴の後ろに加える全域細分 |
|---|---|
| 初期・探索候補 | 0、1、2回 |
| 最終候補 | 1、2、3回 |

すべての水準を既存の実FEMで解き、同じ座標/水準が前試行にあっても最終確認を省略しない。
元の固定分割・品質条件・源メッシュ・規格化・RF座標を各試行で再検査する。
分割の親接続が変わった場合は、FEM前に失敗を保存する。
制約未確認/未達の候補へ有利な目的関数値を与えず、元の総試行予算に最終確認を含める。

表面細分評価は、履歴を使用した場合だけ版2になり、`refinement_sequence`を保存する。
`fixed_prefix`は最初の水準の履歴から末尾のuniform段階だけを除いた共通接頭部分。
各後続水準は同じ接頭部分にuniformを追加したものだけを許す。
`refinement_level`はその接頭部分の後のuniform回数であり、
元Projectにも末尾uniformがあればその回数を含む。
Caseの`curved_refinement_levels`や局所細分の総段数とは区別する。
途中挿入・別markedへの変更・逆順・RF条件変更・元メッシュの変更は拒否する。
履歴を持たない従来入力の版1文書・行・意味は維持する。

表面評価の版2を内包しても、RF設計評価と探索checkpointの外側の版は従来の1を保つ。
既存の再生は保存場から内側の版/固定履歴を再構築し、JSONの宣言だけを信用しない。

## 操作

合成球形に固定marked段階を加えた実行例:

```sh
OPENBLAS_NUM_THREADS=1 .venv/bin/python -m superfish_ng optimize-rf \
  examples/optimization/frozen_history_rf.json --out out/rf-history-new --max-new-trials 1
OPENBLAS_NUM_THREADS=1 .venv/bin/python -m superfish_ng resume-rf-optimization \
  out/rf-history-new/checkpoint-001.json --out out/rf-history-resumed-new
```

GUIでは局所分割を固定してから「現在の形状と設定から入力を作る」を選ぶ。
履歴があると版2を作り、読み込んだ要求の版も保持する。
元履歴を保って追加細分したことを結果へ表示する。
保存された表面評価は「表面ピークの細分評価」から開ける。
表の段数は固定履歴末尾の追加全域細分を意味することを表示する。
保存要求、checkpoint、対象IDの各水準の元場は従来の操作で開く。
