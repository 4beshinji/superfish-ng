# TE分割切替のGUIと実円弧検証

開始HEAD `9fcb810`、2026-09-15 JST。前段で接続したTE対称のStudy版4・調整版8を検証する。
対象を次の3経路に分ける。

- 折線側壁の磁気対称z_max鏡映：調整版8の実GUI。前段のAPI/CLI結果と全保存場を比較する。
- 円柱部＋円弧端部の磁気対称z_min鏡映：Study版4の独立APIと逐次GUI。
- 同じ円弧形状：円弧辺の分割変更を含む調整版8のAPI・保存再開。

受入条件は、元要求/分割予定/参照座標の保持、実Eφと元セクター順位、保存再開と改変拒否、
最終細分の目標差/粗細差の別判定、独立体積、保存配列/RF一致である。
製品コードと検証器は変更せず、既存の実行経路を検証する。

## 実円弧の2種類の交換

旧円弧Studyの形状から明示した55要素の元メッシュを作り、境界辺を1つ分割した56要素へ交換する。
軸辺の分割は同じ表現P2境界を保持するのでStudy版4が受理する。
円弧辺を分割すると表現P2境界が変わり、Study版4は二次境界不一致として拒否する。
調整版8は、量子化した明示参照頂点とその厳密な中点を使い、両分割の全参照被覆を検査して受理する。
参照座標の量子化は対応宣言にのみ用い、物理メッシュの座標を丸め直していない。

分割前後の半領域P2体積は0.0020452922161048274と0.0020452929272176874 m³で、同一ではない。
各分割のx=0を基準に、形状変更の体積増分を独立式と照合した。
Studyの直線部伸長では `πR²·0.03125·x`、指数式調整では `πR²·0.03125·expm1(x)`（R=0.0625 m）。
許容差1e-14 m³を満たした。異なるP2境界の絶対体積を同一と主張せず、幾何差を記録する。
これは合成形状であり、測定された構造や連続領域の誤差上限ではない。

## 実行記録

円弧入力・幾何・APIは `out/te-cap-partition-20260915/`。
調整GUIは `out/te-partition-gui-20260915/tune/`、円弧Study GUIは上記円弧記録の `gui-sequential/`。
GUIは既存の専用workspaceへ一意の新ジョブを追加した。従来の3ジョブは今回の計算数に含めない。
逐次GUIの読み込み待ちは、前段で追加した引数により600秒上限とした。

調整版8のGUIは12項目PASS。フォームの単位・式・Project・controlsを完全一致で検査し、
重複キーをworker起動前に拒否。2試行で停止した後、分割予定と比較版5の参照座標を復元する。
保存テキスト一致、再生、改変拒否、保存要求からの再開、両1 MHzゲート、最終場のIDとTE非該当量を確認した。
結果画像でも、元対称セクター内の順位と全スペクトル順位の区別を確認した。
既存workspaceの3ジョブは別途読み取り検査を行い、64ファイルのhash保持を確認した。追加固有値計算0。

実円弧StudyのGUIは8項目PASS。元3点の保持、最初の1点で停止、保存テキスト一致/再生、
改変拒否、保存要求からの再開、実EφのID、完了再生を確認した。画像でも3点の採用と再開禁止を確認した。
今回の5つの新GUIジョブはすべてcomplete、両ブラウザーは終了0、専用サーバーもSIGINT終了0。

円弧調整の最初の要求はmax_pair_tests=300000で、2試行からの再開時に、最終細分の参照分割が
604450組を必要として予算超過で停止した。3つのnative場とfailure-003.jsonを保持した。
チェックポイントの要求は不変なので、予算だけを700000へ変更した新しい要求を別出力で実行する。
物理閾値・形状・メッシュ・目標・RF規約は変更しない。この停止を物理的UNVERIFIEDやTUNEDと混同しない。

700000組の要求では、2試行の保存から再開してTUNEDの最終チェックポイントを保存した。
参照分割604450組と参照辺8372組の計612822組を検査した。最終粗細差43,511.077178 Hz、両1 MHzゲートはtrue。

保存場の照合は13組・104 NPZ配列と全RF量が完全一致した。
GUI分の7組56配列は先に照合し、ソースと172ファイルのhashを照合して、その成功結果を後段へ再利用した。
後段では元円弧の初期/最終場、予算超過時の3場、新要求の3場を追加比較し、重複を除く289 nativeファイルを保持した。
計算予算の変更によりFEM結果が変わっていないこと、円弧分割を含む実Eφと全鏡映体積も確認した。
補助集約スクリプトは当初plot cacheをジョブに数えて停止したため、job.jsonを持つディレクトリだけを数えるよう修正した。
その失敗ログは保持し、配列照合や追加FEMを行う前の集約上の誤りとして区別した。

新規固有値計算は15半領域分。GUI6、円弧独立Study3、最初の調整3、予算変更後の調整3である。
最初の調整の3場は保存されているが、予算超過した最終試行を元要求の周波数評価として受理していない。

最後の履歴再生も成功し、増額した要求の実行handleは終了0で終端を回収した。
336製品ファイルのSHAはGUI/API開始時・最終時に一致し、外部HTTP要求0。
製品コード・検証器・依存を変更していないため、unittestとfull/seed validatorは再実行していない。
hosted CIも実行していない。初回予算超過と補助集約の失敗は成功結果に書き換えず保持する。

[集約結果](../benchmarks/tuning/te-partition-gui-cap-20260915.json)には、再実行用の自己完結した
3入力（GUI調整、円弧Study、予算700000の円弧調整）も収録した。
数値参照元は前段の独立FEMと既存の合成形状で、新たな外部資料は使用していない。
TE向け置換計画自動生成・他物理/D03などは残り、全計画goalは継続する。
