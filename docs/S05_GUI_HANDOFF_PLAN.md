# S05: 検証済み磁気後処理量のGUI受渡し

2026-09-13 JST。後続限定課題。[実装記録](S05_GUI_HANDOFF.md)の専用API範囲で限定受入。

親S05の実装欄は「多極・力・トルクの後処理、GUIへの量の受渡し」を要求している。現状の `gui.py` と `gui_hphi.py` / `gui_planar.py` はRF専用Project/Jobを扱い、磁気多極・力の報告を扱う入口はない。静磁場Case編集や全ソルバーのGUI化を、この量受渡しの必須条件へ暗黙追加しない。

対象は、元nativeを明示して厳密に再計算・照合できる平面磁気多極報告と力/仮想仕事報告。線形/B-H/反跳のうち受入済みの形式・版・要素次数だけを許す。元native 5ファイルと報告を明示的に取り込み、既存の専用replay APIで検証する。元ファイルを上書きせず、コピーのSHAと再検証によって出典を保持する。RF Projectへ静磁場を読み替えず、専用の報告取込経路を設ける。

多極は元physics、座標原点、基準半径[m]、回転角[rad]、normal/skewの絶対T、次数と明示規約を表示する。元FEMの4標本系列、角度数/内外半径差と再構成残差を別診断として表示/ダウンロードできる。相対10^-4単位や磁石長を自動導入しない。

力は対象region、原点[m]、Fxy[N/m]、重み付きトルクと節点回転応力トルク[N m/m]を別名で表示する。仮想仕事nullは「未実施」とし、零や合格へ変換しない。仮想仕事ありは刻み、実差分、対応する応力、差を表示する。非線形失敗が保存された材料報告は失敗として表示し、完了済みの系列と失敗した刻み/Case/履歴を参照できるようにする。失敗した対のnull差分を零と表示しない。全報告のダウンロードを保持する。

既存のローカルセッション認証・厳密action要求・出力整合性と非上書き保存を継承する。画面上の再表示/ダウンロード前に元nativeと報告の改変を確認する。長い再求解は既存の非同期Job/worker運用に合わせ、画面の応答を保つ。具体的な専用Job形式は実装前に既存managerとの境界を確認して決定する。

受入はAPIの数値と画面値の一致、単位と二つのトルクの区別、null/失敗/零の区別、原点/半径/回転規約、元Caseと材料出典の保持、改変された元/報告の拒否、再起動後の再読込。独立ブラウザー操作で線形/B-H/反跳、多極と非零力/トルク、仮想仕事あり/なし/実失敗を確認する。HTTPを実行していない環境でブラウザー合格を主張しない。標準回帰と既存RF GUIの維持も必要。

この工程は後処理量のGUI受渡しの限定受入である。軸対称力、未対応デッキや版、静磁場の包括的GUI編集は別課題。S05親の受入は多極・力・独立仮想仕事・GUI受渡しの実績を最後に横断照合して判断する。

2026-09-13 実装前のJob境界決定：既存JobManagerのキュー・子プロセス・中止・再起動検出を共有し、kind=magnetic_report_importを追加する。元5ファイルと報告を専用source/とreport.jsonへ所有コピーし、コピーのSHA、専用実FEM replay、取込前後の元SHAを照合して最後に完了manifestを公開する。完了は報告の検証・取込完了であり、保存されたvirtual_work_failedを科学的成功へ変更しない。保存済み報告の要求・係数・履歴を改変しない。

read_jobによる専用検証は全FEM replayを実行する。画面ではその重い初回/再起動後検証を読取専用の非同期処理へ送り、完了までverifyingを表示する。検証済みの全対象ファイルSHAと結果をそのサーバーのメモリーに保持し、以後の表示/ダウンロードも毎回SHAを照合する。変更したファイルはキャッシュを使って表示しない。再起動でキャッシュは消え、再度全FEMを検証する。バックグラウンド検証は元/所有ファイルを書き換えず、サーバー終了後の結果は公開しない。

軸を含まない線形P1/P2の軸方向力保存が先行工程で限定受入されれば同じ画面へ接続する。Fz[N]と全周ポテンシャル[J]を別欄に表示し、平面N/mや断面回転トルクへ読み替えない。これにより次工程の画面は平面多極、平面力、軸非接続軸力の3種類を明示選択せず報告の厳密形式で識別する。
