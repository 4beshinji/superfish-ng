# 境界分割が異なる多角形の厳密アフィン共通分割

P02の残件「境界密度を独立に選べる再メッシュ合成」の幾何APIを追加・限定受入した。
`exact_affine_polygon_overlay` は、二つの元メッシュを、宣言したアフィン写像の下で
厳密に共通分割する。追跡要求の保存・ID判定・worker・CLI・GUIへの接続は後続工程。
既存の追跡版1〜6は変更しない。

## 入力と評価する写像

```python
from superfish_ng.planar_tracking_exact_affine import exact_affine_polygon_overlay

overlay = exact_affine_polygon_overlay(
    previous_mesh, current_mesh,
    linear_xy=[[1.0, 0.25], [0.0, 1.0]],
    translation_xy_m=(0.0, 0.0),
    inverse=False,
    max_candidate_tests=2_000_000,
    max_overlay_triangles=250_000,
)
```

元と現在は単一の直線PEC多角形を覆う `PlanarMesh`。
境界節点数、内部節点、対角線、要素数、番号は独立でよい。
`linear_xy`、移動量と元座標のbinary64値を、それぞれ正確な有理数として扱い、
`x_current = A*x_previous+t` を有理数のまま評価する。
`inverse=True` では同じ宣言の `A^{-1}(x_previous-t)` を有理数で計算する。
行列式は厳密に非零、入力成分は有限、移動量はm、予算は正の整数を要求する。

入力メッシュを再検証し、実境界の余分な共線節点を除いた巡回列と宣言多角形を
厳密照合する。その後、変換した元多角形の角列と現在の角列を厳密照合する。
反射では巡回方向を反転し、開始位置は正規化する。写像を頂点から推定しない。
元/現在の境界が宣言線分から1 ULPだけ曲がっていても拒否する。

これは[版6](PLANAR_AFFINE_REMESH_TRACKING.md)の「既知の浮動小数点演算順で
境界節点列が完全一致する」契約とは別のAPIである。版6で受理できる丸めた角列でも、
厳密なアフィン像でなければ本APIは拒否する。一般の丸めた角/境界の対応、
非線形変形、曲線断面は未対応。

## 元要素の被覆と場の評価

変換した元節点をbinary64メッシュに作り直さず、有理数三角形のまま扱う。
既存のBVHは有理数座標配列で再利用し、境界箱・中心・比較も有理数に保つ。
狭い交差を境界箱の内向き丸めで失わない。候補予算は従来どおり木の節点比較と
葉の比較の両方を数え、分割数上限は入力要素数と生成三角形数に適用する。

既存の有理数クリッピングで交差領域を三角形に分け、両側の各元要素について
交差分割の面積和が元面積と厳密に等しいことを確認する。
反射した元三角形はクリップ時だけ正の向きにし、重心座標は元の頂点順へ直接戻す。
要素番号や元場の係数は変えない。正逆とも積分測度は**現在の物理xy面積**。
返却する `reference_determinants` は分割三角形の面積の2倍である。

全被覆確認後に、積分用の座標・重心座標・行列式をbinary64へ変換する。
非有限値やゼロへ潰れた行列式は拒否し、配列は読取専用とする。
この変換後の積分自体は浮動小数点演算であり、厳密面積証明と区別する。
元要素のP1/P2多項式は返却した重心座標で直接評価できる。
再補間・節点平均や固有値の置換は行わない。

TE電場を比較するときの移送は既存の宣言則 `adj(A)=det(A) A^{-1}`、
TMの縦電場はスカラーである。逆宣言では有効行列を `A^{-1}` として扱う。
本APIは場の移送やモードID判定を自動実行するものではない。
一般のせん断対応を固有モードの物理的同一性、真の誤差上界や連続追跡と呼ばない。

## 先行反例と受入条件

単位正方形を3×3と4×4に独立分割し、後者へせん断
`[[1,1/4],[0,1]]` を与える。境界辺は12本と16本で、厳密面積は両者1。
旧版6のAPIは境界節点列の不一致で拒否する。
前の内部節点を変換してbinary64へ丸めると `1/72057594037927936` の差が出る。
新APIはその丸めを避け、各元要素の厳密被覆を確認できる。
反例は `out/exact-affine-overlay-20260912/counterexample.json` に保存。

受入条件は次の独立検査である。

- 面積と単項式積分の閉形式、各元要素への重心座標復元、反射/逆変換/三尺度。
- 非二進有理数となる逆変換、凹領域・共線角・番号変更、1 ULP領域差/境界ずれの拒否。
- 有理数BVHと独立総当たりの候補一致、浮動小数点に丸めると消える交差の保持。
- 不足/重複した候補の故障注入で各要素の被覆検査が拒否すること。
- P1/P2・混次数・TE/TM多項式の元場積分と余因子移送、3次/5次積分一致。
- 別々に細分した反射矩形の実FEM/native再読込を、解析f・全E/H・G/Q/壁損失と別判定。
  二尺度の周波数・規格化・単位長RF相似則、標準全体、既存seed周波数/RF回帰。

検証コマンド：

```sh
python -m unittest discover -s tests -p test_planar_tracking_exact_affine.py -v
OPENBLAS_NUM_THREADS=1 python scripts/validate_planar_exact_affine_overlay.py --out out/exact-affine-new
OPENBLAS_NUM_THREADS=1 python scripts/validate.py --out out/validation-exact-affine-new
```

## 検証記録

追加8unitは1.414秒で合格。独立検証は16条件・32実FEMと32native保存再読込が
158.862秒で合格した。対象はTE/TM各基本モード、P1/P2、両尺度、元16→32と
現在24→48の独立分割・反射である。各解析誤差とGram差の細分改善も必須とした。
最終標準は964件（962合格・2 skip、1523.747秒）で合格。
`OPENBLAS_NUM_THREADS=1 python scripts/validate.py` の収束計算も終了0。
既存 `benchmarks/validation` のpillbox/shaped_cell計9モード19量は、
周波数差0、最大相対差8.882e-16で一致した。ベンチマークは更新していない。
標準/独立の551ファイルのhash一致と、前回受入済み548ファイルが不変であることも確認した。
標準証拠は `out/validation-exact-affine-overlay-20260912`、
照合結果は同ディレクトリの `seed_regression.json`。
環境はPython 3.12.3、NumPy 2.5.2、SciPy 1.18.1。
既存の `.manager.lock` のResourceWarningは今回も観測し、未解決のまま保持する。

失敗履歴：

新規8unitの初回は、約1e5の自己内積に対して約1e-12の丸め誤差を持つ
理論上ゼロの交差項を、成分別相対差で比較したため1失敗。
ノルム積で無次元化したGramの絶対/相対3e-12判定へ検査式を修正し、8件合格。
これは既存の製品許容差や精度ゲートの緩和ではない。
独立検証器の最初の呼出しは `save_planar_run` のCase引数不足で失敗した。
両失敗ログは同じoutディレクトリに保持する。

独立検証run2のP2 TMは元16×16/現在24×24でG誤差0.00939884、
磁場L2誤差0.00378772となり、0.005/0.002の基準を満たさなかった。
閾値を維持し、P2も16→32（現在24→48）の系列へ細分して再検証した。
周波数と電場Gramの小さい差だけではRF/磁場の合格にならない反例として保持する。

初回標準は `OPENBLAS_NUM_THREADS` 未指定で956件を実行し、1387.555秒、
2 error・2 skipで終了した。曲線適応の1件は実行中の新ソース追加を検出した
`implementation changed during curved adaptive refinement` であり、
この実行は固定ソースの基準検証として扱わない。
もう1件はRF最適化ジョブの `RF optimization replay differs from saved data or sources`。
workerはBLASを1スレッドに固定するが初回親プロセスは未固定だった。
スレッド数差が原因かは未確定だが、固定ソース/1スレッドの最終標準では両検査とも合格した。
初回全文は `out/baseline-20260912-boundary-remesh.log` に保持する。
1スレッド固定のRF最適化ジョブ個別再検査は、製品変更なしで4件合格（206.014秒）。
証拠は `out/exact-affine-overlay-20260912/rf-jobs-recheck.log`。
初回の不一致原因を切り分けたことにはせず、未固定環境の再現性確認は残す。
