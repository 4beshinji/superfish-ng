## 確認できた1987年版

DOE OSTIから取得したM. T. Menzel / H. K. Stokesの
[User's Guide, LA-UR-87-115](https://www.osti.gov/servlets/purl/10140823)は表紙にJanuary 1987とある。
[UNTの政府資料目録](https://digital.library.unt.edu/ark:/67531/metadc1314374/)も同報告を識別する。
取得PDFは210ページ・9,489,185 bytes、SHA256は
`6ba0f0374057bd3f2bdcb55a62247d0f820187b7039dafd51820087e97234851`。
PDF作成日の1997年と報告書発行年を区別する。本文テキストを抽出できないため画像で照合した。

参照した入力仕様は§2.2.3と表2-2、印刷ページ2-9〜2-12
（取得PDFの1始まり39〜42ページ）。この版の説明は次の範囲である。

| 項目 | 1987年版で確認した記述 |
|---|---|
| NT=2 | 中心X0/Y0を持つ円弧。非円楕円やA/Bの指定はこの表にない |
| NT=1/2の端点 | Cartesian X/Yまたはpolar R/THETA。中心移動を指定した端点座標は移動原点からの値 |
| THETA | 度、X軸から反時計回り。これだけで弧の掃引方向・長短の選択規則までは確定しない |
| NT=3 | 第1象限、Y=Xに対称。Cartesian X/Yと必須R。X0/Y0、THETAは使わないと表にある |
| 双曲線のR | 原点から枝への最短距離。本文は2XY=R²、表のNT欄は2XY=Rと記載が食い違う |
| 点の許容差 | 円・双曲線とも本文は相対10⁻³。次元付き位置誤差や受理後の端点処理を規定した値ではない |

上表は[原本の入力仕様](https://www.osti.gov/servlets/purl/10140823)の要約であり、
7.17の仕様への読み替えはしない。特に、R25で記録されたNT=2楕円やNT=4/5と
1987年版の表を組み合わせても、一つの確認済み文法にはならない。
NT=3の表の式はRが長さという定義と次元が合わない。
本文の式は最短距離の定義とも整合するが、これを対象実行版での動作確認とはしない。

CERNの[2010年講義一覧](https://cas.web.cern.ch/schools/ebeltoft-2010)と公式Indico時間割も調べた。
検索に現れた「Superfish Exercise」の転載は一次資料の探索手掛かりに留め、
その抜粋から7.17の省略値や原点規則を確定していない。
USPASのマニュアル取得は403、UNTの直接PDF取得はPDF以外を返し、OSTIからの取得が成功した。
推測した旧CERN講義URLは404だった。取得失敗を文書不存在や機能非対応の証拠にしない。

## 独立に検査した幾何対応

以下は上の陰関数から自前に導出した数学上の対応であり、AF parserの新しい受理規則ではない。
R>0、X,Y>0、2XY=R²に対し、u=log(Y/X)/2と置くと

`X=R exp(-u)/sqrt(2), Y=R exp(u)/sqrt(2)`。

nativeでは中心(0,0)、半軸(R,R)、branch=1、回転π/4の`HyperbolaArc`に一致する。
両端のuをそのまま開始/終了に使い、R/sqrt(2)を半軸にしない。
SI変換係数をsとすると半軸は(sR,sR)、uは不変である。
開弧の符号付き線積分1/2∫(X dY−Y dX)はR²(u_end−u_start)/2。
頂点はX=Y=R/sqrt(2)、原点からの距離はRである。

円は明示された中心・R・開始角・掃引角から`EllipseArc`の半軸(R,R)へ対応する。
この式は旧入力が掃引角をどう決めるかを補わない。
検査例は自作の両向き四分円と矩形双曲線。実在加速器の形状は再利用していない。

3尺度×3半径×2方向をそれぞれ検査し、計36弧・612点について陰関数、
双曲線の指数関数による座標/勾配との接線直交/頂点距離と、両種の線積分が合格した。
最大の無次元誤差は1.1102230246251565e−15（検査条件5e−14）。
Rの二乗を落とす式と、半軸をR/sqrt(2)にする誤変換の2つを負例として検出した。
既存src/tests/scripts/examplesの988ファイルは開始終了で不変。

実行は `out/c00-conic-input-spec-20260914/check-neutral-geometry.py`、
結果は同 `neutral-geometry-report.json`。製品に変換器を追加した検査ではない。
今回の変更は文書・参照台帳だけで、FEM/既存unittest/seed/全validate/GUI/Hosted CIは再実行していない。
原PDF・閲覧画像・探索記録はignored out/だけに保存し、ソース配布に含めない。

## NT=2/3を実装する前の確認と受入条件

| 確認項目 | 必要な証拠と変換後の検査 |
|---|---|
| 7.17向け付属仕様 | 文書改訂日/hashとPO表・詳細節。過去のSFCODES.txtと同じならhashを照合 |
| 省略値と引継ぎ | NT/X0/Y0/A/B/R/THETAをPOごとに初期化するか。必須値を欠く入力の位置付き拒否 |
| NT=2の支持と掃引 | 半軸の意味、Cartesian/polarの基準、長短弧・半周・同一点・両座標指定。両向きと角度の枝切りを検査 |
| NT=3の支持と枝 | 移動原点と許される象限、Rの定義。陰関数・最短距離・単位・方向反転を検査 |
| 丸めた端点 | 許容差の定義と受理後の座標。元の点・曲線へのずれを記録し、既存Caseの接合許容差を緩めない |
| 接線操作 | 旧操作で入力する量を特定し、生成点/接線/曲率とnative構築の候補を照合 |
| API/CLI・保存 | legacy_input.pyとcli.pyが直接の利用先。原入力バイト/位置/SI/変換版を保持し、旧NT=1/4/5の結果を保持 |

| 旧数値との照合 | 許可済み既設実行環境が利用可能になったら、合成入力を両側で細分。モードの場対応、f、RF、表面場を分けて記録 |
