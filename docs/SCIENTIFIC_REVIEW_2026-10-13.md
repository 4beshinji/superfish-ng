# Superfish NG 既存実装の科学的妥当性レビュー

2026年10月13日。対象は独立実装 Superfish-NG の基準コミット
`46655618abcde6ff82dbbfd1296fe76bb97fe279`。過去の実装を現行コード、解析解、
保存された受入証拠から評価した。旧SUPERFISHの内部実装や全コミットの逐次監査は対象外。

**中心となる真空軸対称TMの定式化には妥当な数学的根拠があり、解析解への収束も再現した。
一方、直線TMで異なる入力と解を組み合わせた結果を保存・再読込できる不具合を確認した。
したがって、限定された物理と収束確認済みの問題に対する研究用ソルバーとしては支持できるが、
任意の入力・保存結果の科学的整合性、一般形状の精度、実機予測の妥当性まで一括して保証できない。**

今回の既存テストは15モジュール92件すべて合格し、失敗・skipは0件だった。
追加した独立解析比較と入力差替え検査は、この92件とは別である。
不具合の修正や受入許容値の変更は行っていない。

## 主要所見

優先度は対処の順序であり、各行をすべて数値ソルバーの欠陥と解釈しない。
再現済みの不具合、静的に確認した検証上の欠落、使用条件を分ける。

| ID | 優先度と根拠 | 所見 | 判断 |
| --- | --- | --- | --- |
| S01 | 高・新規再現 | 直線TMの入力と実解の対応をRF評価・保存・読込が十分に検証しない | 科学的に矛盾する完了成果物を生成できる。公開APIの修正が必要 |
| S02 | 中・コード確認 | 総合validatorのソースhashは実行後だけ。開始時との一致を総合PASS条件に含めない | 過去レビューF01が残存。専用の前後監査を持つ受入記録とは区別する |
| S03 | 使用条件・新規数値確認 | 小さい固有値残差、良い周波数精度から電場・軸電圧・表面ピーク精度を推定できない | 量別の収束判定を維持する。今回のP1例で差を定量確認 |
| S04 | 使用条件・既存証拠確認 | 曲線幾何、求積、有限空間のモード対応、連続物理誤差は別の問題 | N03/P07の限定受入は支持。全形状の誤差上界や縮退中の個別ID保証へ拡張しない |

| S06 | 中・文書照合 | PHYSICS本文に、後続受入で更新された機能を未受入とする古い現在形が残る | 現行仕様と日付付き履歴を分離し、適用範囲の誤読を防ぐ |

## 定式化と実装の評価

### 軸対称TMの弱形式と軸上処理

`exp(+iωt)`、真空、m=0、`H=Hφ eφ` とすると、`u=Hφ/r` に対して

\[
K(u,v)=\int_\Omega r\{(2u+r u_r)(2v+r v_r)+r^2u_zv_z\}\,dr\,dz,
\qquad M(u,v)=\int_\Omega r^3uv\,dr\,dz
\]

となり、`Ku=(ω/c)²Mu` を解く。
[fem.py](../src/superfish_ng/fem.py) はこの非負のcurlエネルギー形式を直接組み立てている。
PECは自然条件であり、壁の `∂nHφ+n_r Hφ/r=0` と整合する。
軸上のuを零に固定せず、Hφがrとともに零へ向かう正則化を使う点も適切である。
[solver.py](../src/superfish_ng/solver.py) は磁気対称面だけを本質拘束し、残差を自由行で評価する。

直線P1の剛性被積分関数は3次、質量は5次で、Duffy変換のJacobianを含めても
4点ずつのGauss則で積分できる。直線P2は[high_order.py](../src/superfish_ng/high_order.py)の
5点ずつの則を使う。軸接続TMというスカラー縮約の範囲で、節点P1/P2を使う理由が成立している。
この確認を一般3Dベクトル電場やm>0への適用根拠にはしない。

曲線P2は[curved_fem.py](../src/superfish_ng/curved_fem.py)で物理勾配、半径、detJを使用する。
曲線写像では勾配に逆Jacobianが入り、直線要素の多項式完全積分の議論はそのまま成立しない。
固定二次領域での場の細分、解析境界への幾何細分、求積次数変更を別に調べる既存方針は妥当である。

### 場の位相とRF規約

canonical TMは `Hφ=ru`、`E=-i Ẽ`、
`Ẽr=-r u_z/(ωε0)`、`Ẽz=(2u+r u_r)/(ωε0)` を実装する。
軸上Ezは `2u/(ωε0)` から評価し、Hφ/rを0/0として扱わない。
専用Hφ経路の `field=real+i*quadrature` とは、同名のquadrature成分の符号規約が異なる。
現在の文書はこの違いを明示しており、単純な配列名一致で比較しないことが必要である。

[rf.py](../src/superfish_ng/rf.py)の
`U=∫(ε|E|²+μ|H|²)dV/4`、`P=Rs∫|Ht|²dS/2`、`Q0=ωU/P`、`G=Q0 Rs`、
`dV=2πr dr dz` と `dS=2πr ds` はpeak phasorと整合する。
端板の損失を含め、軸と対称面を金属壁として数えない。
R/Qは `|V|²/(ωU)` と `|V|²/(2ωU)` を別名で出力する。
係数2の異なる規約と摂動的壁損失の扱いは、Jensenの公開原稿の式25・27・29・33と
§3.9.1でも確認できる。[RF Cavity Design](https://arxiv.org/pdf/1601.05230)

Q0は理想PEC固有場に常伝導表皮抵抗を適用した推定である。
放射、結合器、誘電損失、超伝導BCS損失、熱変形による離調まで含むQや周波数とは解釈できない。
これは明示されたモデルの限界であり、今回確認した式の誤りではない。

## 新規に再現した不具合 S01

直線TMの `Solution` は、通常の求解で元Caseを拘束情報として保持していない。
`quantities` はTE・曲線解ではCase一致を検査するが、直線P1/P2には同等の検査がない
（[rf.py](../src/superfish_ng/rf.py)、68行以降）。
`save_run` も直線解では主に次数を照合し、受け取ったCaseのhashを付けて完了マーカーを公開する
（[io.py](../src/superfish_ng/io.py)、41行以降）。
通常生成メッシュの `read_solution` は配列・Case間の文書一致・hash・軸CSVなどを検査するが、
宣言形状と実メッシュの一致、正規化エネルギーをここでは確認しない
（[saved.py](../src/superfish_ng/saved.py)、16〜179行）。外部メッシュには別の照合分岐がある。

実験はR=0.1 m、L=0.2 m、1 J、nr=nz=8の実FEM解を使用し、
有効な別Caseを渡した。係数・メッシュの書換えやhashの偽造はしていない。

| 入力の差替え | P1 | P2 | 破られる物理・対応条件 |
| --- | --- | --- | --- |
| 半径を0.2 mへ変更 | RF評価・保存・再読込すべて受理 | 同左 | Case半径0.2 mに対し実メッシュ最大半径0.1 m。TM010のf∝1/Rと対応しない |
| 長さを0.4 mへ変更 | すべて受理。Eaccが元の1/2 | 軸電圧区間検査で拒否 | P1では実積分区間0.2 mと宣言長さ0.4 mが混在 |
| 正規化を9 Jへ変更 | すべて受理 | 同左 | 保存Caseは9 J、RFのstored_energyは約1 J |

半径差替えのP1周波数は1147.498644588 MHzのままだった。
R=0.2 mの解析TM010は573.712639176 MHzであり、丸め誤差や細分誤差では説明できない。
P2でも半径差替えを受理し、1147.425658739 MHzを保存した。

最小再現の骨格は次のとおり。出力先は未使用の名前にする。

```python
from dataclasses import replace
from superfish_ng import Case, solve
from superfish_ng.io import save_run
from superfish_ng.saved import read_solution

case = Case(((0., .1), (.2, .1)), nr=8, nz=8, modes=1)
solution = solve(case)
other = replace(case, profile=((0., .2), (.2, .2)))
save_run(other, solution, "out/reproduce-case-mismatch-new")
saved = read_solution("out/reproduce-case-mismatch-new")
assert saved.case.profile[0][1] == saved.mesh.points[:, 0].max()
# 現版では 0.2 != 0.1 となり失敗する。
```

**影響は公開Python APIでの入力・解の取り違えと、その成果物を信用する後続処理である。**
通常の `solve(case)` と同じCaseを直ちに保存する操作が誤答する、と確認したわけではない。
また、今回の再現を全専用native readerへ一般化しない。

修正では、元の物理・領域・境界と正規化を解へ結び付け、保存前に不一致を拒否する必要がある。
β、導電率、明示した加速区間など、再求解なしに変更できる後処理条件は区別する。
`quantities` の全Case一致だけを機械的に強制すると、既存のβ変更テスト等の有効な用途を壊す。
受入条件は上記三差替えの拒否、正当な後処理変更の維持、P1/P2・鏡映・外部メッシュ・保存読込の整合、
seedの周波数とRF量の維持である。修正は本レビューの後続作業とする。

## 新しい解析比較と精度の解釈

製品の `analytic.py` を使わず、円筒のJ0/J1解析式から参照値を計算した。
R=0.1 m、L=0.2 m、β=1、U=1 J、σ=5.8×10⁷ S/m。
解析fは1147.425278352 MHz、R/Q acceleratorは約57.7715229 Ω。
J0の正零点とJ1の停留点にはSciPy特殊関数を使用した。
零点の定義は[NIST DLMF §10.21](https://dlmf.nist.gov/10.21)に対応する。

場は公開 `FieldSampler` の元E/Hを、要素ごとの8×8 Gauss則と実3D体積で積分した。
Hから決めた単一符号だけを両場へ共通適用し、振幅fitをしていない。
FEM組立器の行列や製品解析helperを期待値に流用していないが、NumPy/SciPyと物理定数は共有している。
以下はすべて無次元相対誤差であり、百分率ではない。

| 次数 | nr=nz | DOF | 周波数 | HのL2 | EのL2 | R/Q accelerator | G |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| P1 | 8 | 81 | 6.394e-5 | 1.404e-3 | 1.139e-2 | 3.086e-2 | 5.281e-7 |
| P1 | 16 | 289 | 1.680e-5 | 3.692e-4 | 5.808e-3 | 9.576e-3 | 5.304e-6 |
| P1 | 32 | 1089 | 4.258e-6 | 9.355e-5 | 2.920e-3 | 2.866e-3 | 1.727e-6 |
| P2 | 8 | 289 | 3.315e-7 | 3.824e-5 | 8.152e-4 | 1.274e-4 | 3.177e-6 |
| P2 | 16 | 1089 | 2.149e-8 | 4.830e-6 | 2.074e-4 | 9.340e-6 | 2.132e-7 |
| P2 | 32 | 4225 | 1.365e-9 | 6.068e-7 | 5.224e-5 | 6.695e-7 | 1.377e-8 |

この系列ではP1の周波数誤差は約2次、P2は約4次で改善した。
Eはuの微分を使うため、場の誤差は周波数の誤差より大きい。
P1のGは8→16で誤差が増えており、各出力量が毎回単調改善するとはいえない。
P2が有効だったという結論は、この滑らかな円筒問題と測定した分割に限定する。

最細の表面比誤差は、P1でEpk/Eaccが1.037e-3、Bpk/Eaccが1.436e-3、
P2でそれぞれ3.420e-7、7.797e-8だった。
これらは既知の有限ピークを持つTM010の解析対照であり、鋭角形状のピーク保証ではない。

S03の直接例はP1の8×8である。固有値残差は5.863e-15なのにR/Q誤差は約3.09%だった。
32×32でも周波数誤差は約0.000426%、EのL2誤差は約0.292%、R/Q誤差は約0.287%である。
さらに、同じK/Mで計算するUE/UH一致は固有値方程式のRayleigh商に密接に結び付く。
代数的整合性として有用だが、それ自体を独立した場精度証明として数えてはいけない。
独立Bessel場、尺度則、電圧積分、壁積分を別に検査する現行テストは維持すべきである。

## 残る検証上の課題

S02は[scripts/validate.py](../scripts/validate.py)の終端で作る`fingerprints`と`passed`から確認した。
実行開始後にコードが変わっても、それを一般入口だけでは検出しない。
[2026年9月22日レビュー](IMPLEMENTATION_REVIEW_2026-09-22.md)のF01と同じ問題である。
これは過去結果が実際に混在したという証拠ではない。
特にN03は外側の監査で始終不変を確認しており、その受入証拠まで無効と判定しない。
今回もレビュー実行の前後で対象1436ファイルを照合し、差分0を確認した。

S04について、離散場ピークの上下界は、離散解と連続真値の差を含まない。
また、固定P2写像を細分しても元の解析境界には近づかない。
モード追跡の部分空間一致・有限guardは、宣言した比較と有限空間内の診断であり、
未解像モードの不在や連続変形経路の一意な枝を証明しない。
既存文書と結果がこれらをUNVERIFIED/nullに保つ方針は正しい。
ケース固有の収束証拠なしに、最適化の終了やGUIの完了だけから設計値の精度を判断しない。

S05は[B01台帳のK31とV01](development-plan/B01-ledger.md)にも残っている。
実機へ使う際は、公表可能な実寸法と公差、端条件、材料・温度・表面状態、測定方法と測定不確かさを持つ
参照ケースが必要である。少なくともf、場形、RF積分量、表面場を分けた比較を行い、
メッシュ差・幾何差・材料の不確かさを誤差予算として区別する。
既存の合成形状やlegacy一致を実測検証と呼ばない。
