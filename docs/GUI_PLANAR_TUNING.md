# 平面RF調整のGUI

2026-09-15 JST、開始HEAD `7a05092`。D02の平面調整を専用平面ワークスペースへ接続する。
受入条件は、厳密な調整要求の入出力、実workerの投入・結果・中止、保存地点の選択/再検証/再開、
目標と粗細差の別表示、未確認時の周波数未評価、対象IDの実順位による保存場表示、元native保持。
[調整API/CLI](PLANAR_TUNING.md)と[worker](PLANAR_TUNING_WORKERS.md)の数値条件は変更しない。

## 操作

`/planar.html`の「周波数を調整する」で、現在のProject、寸法/倍率、範囲、目標Hz、
目標/粗細の許容差、試行予算、初期ID/対象ID、最終細分を指定する。
矩形の幅/高さは表示単位によらずm、一様倍率は無次元。
追跡条件は詳細欄で指定し、元JSON文字列のままサーバーへ送って重複キーを拒否する。

調整条件は単独ファイルへ保存/再読込できる。同じファイルを再び選べるよう、読込時にファイル選択欄をクリアする。
検証待ちに入力を編集した場合、古い正規化結果で入力を上書きしない。
「今回追加する試行数」を空欄にすると宣言した停止条件まで実行する。
計算履歴の「中止」でworkerを止め、停止後の「保存地点を選ぶ」から完了済みcheckpointを再検証できる。
保存地点のファイル再読込、別ジョブへの再開、URL/ページ再読込による完了結果の復元も扱う。
再開は選択した保存地点の要求を使用し、フォーム編集による要求差替えは行わない。

試行表は探索/最終細分、変数値、対象IDの現在順位、周波数、目標との差、状態を表示する。
最終判定では目標達成と粗細差条件を別々に表示し、TUNED以外を成功扱いしない。
個別ID未確認では「未評価」、場を開くボタンも無効にする。
確認済みの場はnativeを取り込み、その試行で対象IDが占める順位を選択して既存の平面表示へ渡す。
J/m、W/m、加速R/Q非該当を保持する。新しい固有値計算を取込の代わりに実行しない。

## 保存地点の検証

停止した専用planar_tuneジョブに限定して保存地点を列挙する。列挙自体は未検証とし、開く時に完全再生する。
元要求、祖先の試行/ID/場hash、新規試行の所有ディレクトリ、checkpoint番号を照合する。
投入時hashが状態に保持される完了ジョブでは、投入要求の外側データもそのhashと比較する。
共通管理器のcancel/interrupted状態は投入時hashを保持しないため、これらの保存地点では
要求・元場・祖先・所有パスの完全照合が検証範囲となる。不存在の投入時hashを検証済みと扱わない。
取込前後に元nativeのhashを照合する。別ジョブのcheckpoint、改変、未確認対象の取込は拒否する。
