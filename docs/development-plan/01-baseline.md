# 基準と互換仕様の確定

[全体索引と実行規則](README.md)に従う。本章のIDは親課題IDではなく、作業カードID。

各カードは原則1コミット。既存ファイルは調査・変更候補であり、全てを書き換える指示ではない。新設ファイルは本文で指定する。

## B01

### 残要件と証拠を一行ずつ固定する

- **親課題**：C00。**種別**：監査。初期状態：未着手。
- **先行条件**：なし。着手可能。
- **コミット件名案**：`docs: 残要件と証拠を一行ずつ固定する`
- **既存の入口・影響先**：`docs/BACKLOG.md`、`docs/IMPLEMENTATION_STATUS.md`、`docs/COMPATIBILITY_MATRIX.md`、`docs/COMPATIBILITY_PLAN.md`
- **実施内容**：K01〜K32の各F/I/O/N/Wを最新の専用受入文書へ対応付ける。受入範囲・未完理由・担当親ID・本計画カード・証拠の現存/欠落を行単位で記録する。古い経過記録は削除せず、現行表への案内を付ける。
- **受入条件**：全32行と33親課題が対応し、22未受入親に担当カードがある。受入済み10件を再実装対象に戻さず、C02の追加部分集合は別管理する。履歴中の古い未完文言から新しい要件を捏造しない。
- **確認方法**：文書/仕様/監査は差分と根拠・リンク・依存を確認。検証カードは本文指定の専用実行を行い、[共通検証規則](README.md#検証と完了報告)で報告する。文書更新だけでFEMを再実行しない。

- **納品物**：該当差分、カード受入条件ごとの結果と未確認理由、実施したコマンド/終了状態、次の着手ID。数値実行のrawは未使用の`out/`以下に保存し、短い結果と来歴を該当仕様書へ記録する。
- **成果物**：[B01残要件と証拠の対応台帳](B01-ledger.md)（K01〜K32の受入軸対応、親33件の担当カード、C02追加部分集合、証拠の現存/欠落）。

## B02

### 対象版の機能と入力資料を確認する

- **親課題**：C00。**種別**：調査。初期状態：未着手。
- **先行条件**：[B01](01-baseline.md#b01)
- **コミット件名案**：`docs: 対象版の機能と入力資料を確認する`
- **既存の入口・影響先**：`docs/COMPATIBILITY_BASELINE.md`、`docs/PROVENANCE.md`
- **実施内容**：既存の参照台帳から公式入力仕様・付属文書・許可された実行の表示版を確認する。配布物名、各ツール表示版、文書改訂、項目名/既定値/単位/境界/出力を分ける。消失したSFCODES.txtの記載を既定値の根拠にしない。
- **受入条件**：各K行に版と節または明確な未確認理由がある。旧ソースやバイナリ内部を読まない。資料がなければ調査記録をコミットしC00.Vを未確認に保つ。確認できた行だけB03/C01へ渡せる。
- **確認方法**：文書/仕様/監査は差分と根拠・リンク・依存を確認。検証カードは本文指定の専用実行を行い、[共通検証規則](README.md#検証と完了報告)で報告する。文書更新だけでFEMを再実行しない。

- **納品物**：該当差分、カード受入条件ごとの結果と未確認理由、実施したコマンド/終了状態、次の着手ID。数値実行のrawは未使用の`out/`以下に保存し、短い結果と来歴を該当仕様書へ記録する。

- **成果物（2026-09-22）**：[B02対象版・入力資料再監査](B02-reference-audit.md)。32行の版/未確認理由、現存7件のhash一致、R25欠落を記録。調査DONE、C00.VはUNVERIFIED。

## B03

### 必須範囲と不足仕様を確定する

- **親課題**：C00。**種別**：仕様。初期状態：未着手。
- **先行条件**：[B02](01-baseline.md#b02)
- **コミット件名案**：`docs: 必須範囲と不足仕様を確定する`
- **既存の入口・影響先**：`docs/COMPATIBILITY_MATRIX.md`、`docs/COMPATIBILITY_BASELINE.md`、`docs/COMPATIBILITY_PLAN.md`
- **実施内容**：版付き根拠に基づいて各要件の必須/後続/対象外/未確認を整理する。機能の存在とユーザーの必須要件を区別し、未決の採否は論点と実装差を示す。新しい必須要件はL05の手順で独立カードに展開する。
- **受入条件**：確認済み行には入力例・期待量/単位・比較方法がある。未確認を対象外にして帳尻を合わせない。既存ユーザー要件を縮小する判断はユーザーへ具体的に確認し、無回答で確定しない。
- **確認方法**：文書/仕様/監査は差分と根拠・リンク・依存を確認。検証カードは本文指定の専用実行を行い、[共通検証規則](README.md#検証と完了報告)で報告する。文書更新だけでFEMを再実行しない。

- **納品物**：該当差分、カード受入条件ごとの結果と未確認理由、実施したコマンド/終了状態、次の着手ID。数値実行のrawは未使用の`out/`以下に保存し、短い結果と来歴を該当仕様書へ記録する。

- **成果物（2026-09-22）**：[B03必須範囲と不足仕様](B03-required-scope.md)。32行の分類と限定例E1〜E3を固定。未知採否/C00.Vは未確認、要件縮小なし。
