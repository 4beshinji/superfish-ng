# 弧ごとの分割数を保持する

後続実装: [曲線Project一括変形](CURVED_PROJECT_TRANSFORM.md)を追加。曲線tune接続は残る。以下はこの基盤を受け入れた時点の記録。

2026-09-09、D02の曲線/元メッシュ同時変形の前提。
Case第3版のcurved_contour geometryに任意 `segments_per_curve` を追加する。
元の各プリミティブに対応する正整数配列であり、弧のfractionを均等分割する。
例題は `examples/projects/curved_fixed_partition.json`。
未指定の自動分割と旧保存文書は従来の経路を保持する。

楕円等を非等方に変形すると、同じ許容長から求める自動分割数が変わることがある。
元メッシュを変形しただけでは、Caseが指定する弦境界と一致せず拒否される。
明示分割数はこの対応を保持するための入力であり、不一致の検査を取り除くものではない。

## 誤差条件と保存契約

各弧の分割数は、既存の二階微分上界による弦誤差条件を満たす必要がある。
元の `curve.linearize` を指定数上限で実行し、要求を満たせる場合だけその数で
fractionの点を評価する。許容長から接合補正を差し引く既存処理も維持する。
不足時は弧の番号を示して拒否し、指定数を自動変更しない。
配列長/型、bool/ゼロ/負数、総分割数上限、明示nullを拒否する。
Python Caseは `curve_segments_per_curve` のimmutable tupleを用いる。

Caseの弦輪郭構築、曲線二次メッシュ構築、通常出力の幾何近似報告へ同じ指定を渡す。
native保存/再読込と固定幾何StudyはCaseの指定を保持する。
物理形状の比較では分割数を近似条件として扱い、元曲線そのものと区別する。
鏡映時は対称面のプリミティブを除き、残る分割数を同じ順序と逆順で複製する。
全体上限や輪郭妥当性を黙って緩和しない。

GUIに「各弧の固定分割数」を追加。空欄は自動、JSON配列は明示固定。
保存結果を開くと指定を復元し、フォーム編集後も通常のstrict検査へ渡す。
Caseのトポロジーを変更する構築処理へ、古い分割数を自動再割当する機能ではない。
