各小作業をレビュー可能な区切りでコミットする。大きい.Iは要素組立/復元/保存等へさらに分けるが、
.Vまで製品機能全体の完了とは表示しない。未対応の入力を途中実装へ黙って通さない。
仕様決定は既存のユーザー方針の範囲で進め、通常の実装判断ごとに承認待ちを作らない。
範囲・配布・外部資産の扱いを変更する必要が生じた場合は、その具体的な影響を報告する。

依存欄の親IDは原則その.Vの完了を意味する。「.S」は仕様だけで着手できる。
難度は実装/科学検証の相対区分。C00の対象確定前に全体工数を合算しない。

## 実行順と区切り

1. 今回: 実態監査と旧課題状態の更新、K01〜K32対応表、上記作業分割を文書化してコミット。
2. 次回の開始点: C00.S/I/Vで確認済みTM入力部分集合と未確認一覧を作り、C01.Sで共通契約を固定する。
3. 最初の実装群: C02の限定入力読込、R01のRF規約、O01の完了管理、N01→N02の高次場。
   同時実施が必要という意味ではなく、共通schemaと場表現が衝突しない順に一件ずつ完了させる。
4. 軸対称RF実用化: G01→G02、G03、N03、D01→D02→D03。C03/C04で旧入出力と回帰を接続。
   O02-meshは高次場を待たず可能。A01は数値基盤の採用判断に使い、未実施状態を残さない。
5. 追加物理: P01/P02、P03/P04、S01/S02→S03/S04→S05。C00で必要と確定した範囲から実施する。
6. 各到達点: 必須集合に対応するC04/O02/V02を実行し、V01の実機照合状態、L01/L02の採否を含め報告。

3〜5の内部順序は収束/仕様調査の結果で更新できる。依存の変更は理由と影響を記録する。
初期RF実用互換の報告で静的場まで完成したとは呼ばない。全体互換は残る必須集合の受入まで継続する。

## 工数と不確実性の更新方法

以前の会話の概算は機能単体の規模感で、今回の作業群を全て含む納期ではない。
各.S終了時に.I/.Vの工数幅、計算時間、参照データ待ち、依存採用を更新する。
特にC00の版付き仕様、G02のメッシュ品質、N02/N03のRF・ピーク収束、S04の非線形材料が不確実性の大きい箇所。
適応細分や新依存を入れれば自動的に精度問題が解決すると仮定しない。
