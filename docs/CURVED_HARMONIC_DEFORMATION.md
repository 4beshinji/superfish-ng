# 曲線上の対応と調和変位による履歴付きProject変形

2026-09-14 JST、N04残件4の非アフィン形状変更へ進むため、
元の番号付きメッシュと細分履歴を変形するAPI/CLIを追加した。
全体を一つのアフィン写像で表せない、複数の曲線の形状変更を扱う。
各曲線番号と曲線上の分率は明示された対応であり、自動の物理対応推定ではない。

## 受入条件と対象

受入条件は、アフィン変位の再現、独立な変位エネルギー停留、曲線境界の分率/幾何積分、
固定した全段階の接続とP2参照制限、要素反転・品質・予算の拒否、
実FEMの尺度則/場形・保存再構築・非アフィン追跡、CLIの事前検査と既存出力保護。
この段階では変形済みProjectを作成する。一般形状のStudyと専用GUI操作への接続は残る。

```python
from superfish_ng.curved_harmonic_deformation import deform_curved_project

target = deform_curved_project(
    source_project,
    target_geometry,
    rf_coordinates="fixed",
    minimum_corner_angle_deg=1.0,
)
```

入力は未組立・直接構築のnative curved_contour/P2、閉PECと軸だけのTM Project。
TE、反射構築、対称半領域は、この変形契約では明示拒否する。
旧アフィン変形や他の求解経路の受理範囲は変更しない。

`target_geometry` はCaseの `geometry` と同じ厳密なJSONオブジェクトである。
曲線の個数・順番と境界タグを保持する。各曲線の元/先の同じ増加分率を対応させる。
円錐曲線の種類を同じにする必要はないが、全ての曲線と接続が通常のCase検査を通る必要がある。
距離に比例した分率、近傍点への射影、曲線の自動並べ替えは行わない。

元の弦分割数を各曲線に明示固定する。targetの `segments_per_curve` を省略すると元の数を補う。
指定する場合は同じ整数配列だけを受理する。新形状の弦誤差予算も満たす必要があり、
数や許容差を自動調整して入力を通さない。元の弦の途中にある境界節点も対応の対象である。

marked履歴は先に [freeze-curved-refinement](FROZEN_CURVED_REFINEMENT.md) で固定する。
未固定のmarked段階を含む場合は、その操作を案内して拒否する。
固定した分割辺/遷移対角線・元節点番号・境界所属を保持し、
曲線を変更した後に旧整数を新しい自動メッシュへ流用しない。
初期一様細分や後続の一様段階も保持する。

## 境界と内部の移動

1. 元弦メッシュから、各境界辺の曲線番号と両端の曲線分率を取得する。
2. その分率を同じ番号の先の弦へ写す。弦の途中の点を解析曲線へ直接置くと、
   先の弦メッシュとして不整合になるため、この段階では弦上の補間点を使う。
3. 境界変位をDirichlet値とし、元弦メッシュの内部で変位dを求める。
4. 移動した元メッシュから通常のP2曲線境界を構築し、全ての元細分を参照空間で制限する。
   細分後の境界を解析曲線へ再射影しない。

内部のメッシュ変位は、元断面における平面P1エネルギー
`∫ (|grad d_r|² + |grad d_z|²) dr dz` の最小化である。
各三角形で `K_ij = area * grad(N_i) · grad(N_j)` を組み立て、
自由節点Fと境界Bについて `K_FF d_F = -K_FB d_B` を解く。
既存NumPy/SciPyの疎行列と直接解法を使う。新しい依存は不要。

これはメッシュ移動用の平面ラプラシアンであり、軸対称の電磁場方程式ではない。
回転体の体積重みをここへ流用しない。解いた変位を元座標へ加え、境界位置を明示値へ戻す。
アフィン変位はP1空間に含まれ、内部の弱ラプラシアンが零なので再現される。
任意の不規則なメッシュでグラフの近傍平均を取る方法とは、この不変量が異なる。
代数残差の検査は変位の線形方程式を確認するだけで、物理場精度の保証ではない。

変形の対応は、各元/先P2要素の参照写像F₀/F₁による `F₁ ∘ inverse(F₀)` である。
全体がアフィンである必要はなく、物理座標で二次多項式とは限らない。
細分時の同じ参照制限で各子要素にもこの対応が継承される。
P2境界を構築した後の領域全体で、変位が調和関数になるという主張ではない。

## RF座標と拒否条件

`rf_coordinates` は次のどちらかを必須とする。

- `fixed`：元の有効長・電圧積分区間・位相原点を保持する。
- `axis_fraction`：元/先の全軸長の比でそれらを倍率変換する。変形後の全軸長に対する分率を保持するという規約。

未指定の位相原点は未指定を保持する。短縮した形状の外へfixedの電圧区間が出れば拒否する。
このRF規約は、複数の軸曲線の局所分率による節点移動とは別に宣言するものである。
RF正規化・材料・求解・Project表示など、geometry以外の既存設定は保持する。

`minimum_corner_angle_deg` は有限で0より大きく60未満。
接線から測るこの最小角を、変形後の初期空間・全一様水準・全履歴段階で検査する。
履歴に保存された各marked段階の品質条件も、そのまま適用する。
正Jacobian、半径非負、全二次辺の交差/境界、接続、要素予算は既存native検査に従う。
元のメッシュを維持できない場合は拒否し、自動再メッシュへ切り替えない。

## CLIと保存場

[携帯可能な合成例](../examples/curved_harmonic_deformation/source-project.json)は、
軸と二つの半楕円、元メッシュ、marked→uniform→markedの固定履歴を含む。
[先の形状](../examples/curved_harmonic_deformation/target-geometry.json)は二つの半楕円の中心と長さを変更する。
測定された空洞を表す入力ではない。

```sh
OPENBLAS_NUM_THREADS=1 .venv/bin/python -m superfish_ng deform-curved-project \
  examples/curved_harmonic_deformation/source-project.json \
  --geometry examples/curved_harmonic_deformation/target-geometry.json \
  --rf-coordinates fixed --minimum-corner-angle-deg 1 \
  --out out/new-deformed-project.json
```

CLIは幾何/全履歴を検査してから、新しいProjectファイルを排他的に作成する。
既存の出力や元Projectを上書きしない。終了0は変形済みProjectの作成を意味し、
固有値求解・RF収束・モード対応の合格を意味しない。
出力は既存のProject計算・native保存/読込で使える。

元/先の保存場の追跡は、既存の [曲線比較メッシュ版2](CURVED_PIECEWISE_REMESH_TRACKING.md) を用いる。
両Projectのsource_meshとそれぞれの固定細分履歴を宣言すれば、同じ番号付き参照空間で比較できる。
元場の物理体積重みと閾値・部分空間/曖昧判定を保持し、対応するモードIDを幾何番号だけから生成しない。
