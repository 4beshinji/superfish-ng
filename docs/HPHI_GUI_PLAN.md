# 正半径Hφの表示・GUI接続計画

[閉同軸円筒](COAXIAL_RF.md)と[一般断面・複数穴](HPHI_MESH_RF.md)を、
専用HphiProject/ローカルジョブの後に表示・編集操作へ接続する。以下は未実装の次工程。

## 場表示の契約

元nativeを完全再検証し、元FEMセルと元のP1/P2係数から場を評価する。
数値座標は(r,z)[m]、図はzを横軸・rを縦軸にして両軸名を明示する。
Hφのreal、Er/Ezのquadratureを符号付きで表示し、peak exp(+iωt)・real+i*quadrature規約を示す。
このHφ規約を、既存TMのẼ規約へ符号を変えず混ぜない。
図の三角形を細分しても元要素の場を評価し、P1勾配の要素間不連続を平滑化しない。
描くのは真空三角形のみ。穴に色を塗らず、全PEC境界成分を線で示す。
表示分割の最大値を、物理表面ピークの認証値として出さない。

SIプローブは専用nativeの領域検査を使い、内導体内部・軸・外部を拒否する。
CSV/JSONにE/H/Bの全real/quadrature成分、元hash、モード順位と単位・位相を保存する。
Uは全3D[J]、Pは全壁[W]。Q0/G、境界成分・線分別の壁損失、R/Q二規約等のN/A理由を保持する。

## GUIの契約

既存の局所HTTP認証・Host/Origin/token・strict action検査を使う専用画面を設ける。
円筒は寸法と次数・分割を編集し、一般断面は外周・穴・元節点・接続を欠落なくProjectとして保持する。
入力の読込・保存・失敗時の既存内容保持、実workerの開始/中止、所有ジョブへの直接/管理済み取込、
再起動後のProject復元・新しいジョブへの再実行まで接続する。
周波数順位を追跡IDと表示せず、ジョブ完了を精度合格とは表示しない。

履歴ではhphi_solveを専用画面へ開く。既存軸接続や平面の追跡候補へ混ぜない。
nativeダウンロードは元の5ファイルを許可し、パス指定による任意ファイル取得を許さない。
表示cacheは全native hash、実装hash、モード、表示設定を含め、参照中の元変更を再検査する。
nativeディレクトリへ画像/プローブを追加せず、管理器の別cacheへ保存する。

## 受入証拠

1. 両幾何・両次数・二尺度で、図の元配列とプローブ全成分がAPI/nativeと一致する。
2. 円筒TEMと矩形穴の解析固有場を用い、共通位相・規格化・Er/Ezの符号を独立照合する。
3. 穴と凹外周の描画、符号付き色範囲、ゼロ成分・mm/m表示、領域外拒否を実際の図で確認する。
4. 実ブラウザーでProject往復、実FEM、場の切替、プローブ/画像/native取得、中止、取込、サーバー再起動を操作する。
5. ブラウザーの表示量・保存文書をCLI/API/nativeと照合し、元のhashが不変であることを確かめる。
6. 既存TM/TE・平面のブラウザー操作、標準テストと周波数/RF回帰を確認する。

画像生成やHTTP応答だけでブラウザー操作の合格としない。GUI後にも一般の曲線・軸接続の穴付き領域、
HφのStudy・収束診断・追跡、旧版照合と親P03/O02の残工程を区別して維持する。
