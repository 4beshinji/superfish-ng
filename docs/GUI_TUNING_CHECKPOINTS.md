# 周波数調整の途中保存を一覧から開く

2026-09-14：[個別ID回復を組み合わせる外側要求版6](TUNING_IDENTITY_RECOVERY.md)を追加。
本書の入力をtune_requestとして保持し、固定/直近の参照試行と個別比較条件を指定できる。
実際の参照と細分親を区別し、チェックポイント版2・CLI/JobManager/GUIへ接続する。本書の旧版契約は維持する。

2026-09-09、D02のGUI復旧操作。
受入条件は実ジョブの中止・管理器再起動後の選択と再開、
入力/試行の所属/祖先の照合、改変拒否、実ブラウザー操作と既存調整回帰である。

計算一覧で停止済み周波数調整の「途中保存を選ぶ」を押すと、
そのジョブが書いた `execution/checkpoint-NNN.json` を試行数順に表示する。
既定選択は最後の保存だが、前の保存も明示的に選べる。
一覧はファイル名だけの未検証候補であり、再開可能や物理検証済みとは表示しない。
保存がない中止は空一覧となる。実行中のジョブの選択は拒否する。

「選んだ途中保存を再検証して開く」で既存の公開 `replay_tune` を実行し、
元保存場・追跡・判断を再導出する。さらに選択ジョブのrequest、
保存名の試行数、再開前の祖先、今回の試行ディレクトリを照合する。
読込中のcheckpoint/requestの変更とディレクトリ/ファイルのsymlinkを拒否する。
失敗時は最後に検証した画面を保持する。検証後にPAUSEDである場合だけ、
従来の「確認済みの続きから再開」を使って別ジョブとして続けられる。
入力欄の編集は再開条件へ混入しない。

APIは `tune-checkpoints`（id）と `open-tune-checkpoint`（id、正整数index）。
一覧の返却は `id, indices, verified:false`、選択結果は既存の
`document, serialized` 形式。任意ファイルパスを追加で受け取らない。
完了、取消し、失敗、アプリ停止後のジョブに対応する。
書込み途中で壊れた最後の候補は再検証で拒否し、以前の候補を選べる。

APIの5検査は17.017秒で合格。実FEMを中止し、JobManagerを閉じて
再生成した後、最初の保存を選び1試行追加する検査を含む。
別の正当なジョブからの文書差し替え、数値改変、symlink、不正indexを拒否した。
実Chromeは `out/browser-tune-checkpoints-20260909/report.json` の17項目が合格、
外部要求0。既存調整/保存/改変拒否/最終場に加え、保存のない中止、
未検証一覧、前の保存の選択、実中止後の保存から別ジョブでの再開を確認した。
`checkpoint-recovery.png` を実表示して確認。終了時の対象ソースhash一致。
ブラウザーは終了0、GUIも正常停止・終了0。
標準 `out/validation-tune-checkpoints-20260909` は692件中690合格・2 skip、
unittest 471.722秒、全体終了0。seed9モード19量の周波数差0、RF最大相対差
8.882e-16。標準の392対象ファイルと現在のhash、ブラウザー対象hashは一致。
`seed_regression.json` に照合記録、同じoutにAPI検査と実行ログを保存した。
今回の復旧操作を限定受入とし、数値アルゴリズムの新規受入とは区別する。

FEM・追跡・二分法・最終細分ゲートは既存実装を使用する。
一般曲線/非線形変数・制約付き最適化・D02全体は未完了。
