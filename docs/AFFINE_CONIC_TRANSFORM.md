# 弧の対応を保持するアフィン変形

後続実装: [曲線Project一括変形](CURVED_PROJECT_TRANSFORM.md)を追加。曲線tune接続は残る。以下はこの基盤を受け入れた時点の記録。

2026-09-09。D02の曲線形状調整に必要な幾何基盤。
`affine_conics.transform_curve(curve, affine_map)` は既存の線分・円/楕円弧・
双曲線弧を `(r,z) → (a r, b r+c z)` へ変形する。
a,cは正、bは有限で、既存追跡のaffine_mapと同じ厳密入力を使う。
単位は元の長さ単位のまま、三係数は無次元である。

受入条件は、同じ弧fractionの点、接線、曲率、開いた弧の線積分面積、逆変換、
回転と両双曲線枝、範囲逸脱/未解像の拒否、native二次FEM・追跡・相似則と標準回帰。
Case変形、元メッシュの写像、試行間写像の導出、tune/CLI/GUI接続は後続であり、
この基盤だけで一般曲線調整を利用可能とは宣言しない。

## 分解とパラメータ対応

(z,r)順の行列をM=[[c,b],[0,a]]とする。
楕円の中心にMを作用させ、回転・半軸の基底BをMB=U D VᵀとSVD分解する。
左右を正回転に揃えるとVᵀは角度の一定シフトとなる。
新しいstart角へそのシフトを加え、sweepは保持する。
したがって元のfractionに対応する新しいfractionは同じ値となる。

双曲線はbranchを第1基底列へ含め、基底列をu,vとする。
δ=atanh(-2(u·v)/(u·u+v·v))/2を用いる双曲線回転で列を直交化する。
直交化基底の長さを半軸とし、branchを戻して正回転を復元する。
新しい両端パラメータは元の値からδを引く。
cosh/sinhの加法則より、ここでもfractionは保持される。
中心・基底・最終半軸の有限性を検査し、直交性・正方向・基底の再構成を確認する。
軸比が4096ε以下など分解を丸め精度で解像できない場合はUNVERIFIEDとして拒否する。
これは入力範囲の保守的な制限であり、区間演算による厳密な誤差証明ではない。

元の単位接線tに対して、変換接線はMt/|Mt|、曲率はdet(M)κ/|Mt|³となる。
原点を保つ線形変形なので、開弧の面積積分もdet(M)倍となる。
これらを分解式とは独立した検証参照に使用する。

## 確認結果と境界

実装前の独立不変量検査は新APIがなく読込に失敗。その後、点/接線/曲率/面積/逆変換、
strict入力と未解像拒否、native楕円二次FEMの寸法2倍・実モード追跡・f/RQ/Gの
3検査が合格した。native試験は同じ元メッシュを明示的に2倍へ写像している。
新しい幾何近似で再メッシュした境界が等しいと仮定してはいない。

独立乱数検査はseed20260909、楕円/双曲線両枝、寸法1e-5/1/1e5の360例、
各33fraction。位置（寸法で除した絶対差）最大1.777e-15、接線最大1.728e-15、
曲率相対差最大2.887e-15。事前の基準1e-10を満たした。
`out/affine-conics-random-accepted-20260909/validation.json` にsource hashを含め保存。
初回は検証器がnative入力契約で禁止されたNumPy scalarを使い、変形前に失敗。
built-in floatへ直し再実行し、初回記録は `out/affine-conics-random-20260909/failure.json` に保持。
ランダム有限標本を全域の証明と扱わない。

標準 `out/validation-affine-conics-20260909` は698件中696合格・2 skip、
unittest474.010秒、全体終了0。seed9モード19量の周波数差0、RF最大相対差
8.882e-16。独立/標準/終了後の397対象ファイルhash一致。
`seed_regression.json` に照合記録を保存。新規ブラウザー検証はない。
全関連実行は終了し、幾何APIの上記範囲を限定受入とする。

単独弧の変形は閉じた空洞の妥当性を保証しない。
たとえばせん断後にz=[0,L]を外れる輪郭は、既存Case検証で拒否する必要がある。
Caseの寸法制約、境界タグ、元メッシュ、二次写像、RF評価区間等を一括して変形する
製品経路は未接続。軸対称体積の倍率はa²cであり、子午面面積のacと区別する。
一般曲線の調整と親D02は未完了。新規外部資料・依存・legacy参照はない。

## 次の接続点

`jobs._execute_prepared` は現在 `solve(project.case)` を呼び、Projectは
明示元メッシュを保存する項目を持たない。ソルバー自身の `mesh_data` 入力と
native保存/再読込は存在するが、調整ジョブからは指定できない。
独立に再メッシュして境界が同じだと仮定する接続は採らない。

次はO02/D02の依存作業として、Projectに明示メッシュを保持する版付き契約を定める。
必須検査は、旧Project文書不変、タグ/接続/形状のstrict検査、通常CLI/API/Jobの
同一メッシュ実計算、保存後hash/再構築、入力改変拒否と中止/再開である。
続いて元曲線・元メッシュを同じ写像で変形し、試行間はM_current M_parent⁻¹を
導出する。最終細分は同じ写像のままnative二次空間を細分する。
RF評価長/区間・最小曲率などの物理/製造条件を黙って伸縮する仕様にしない。
各条件の固定/連動を明示し、幾何・メッシュ近似と物理誤差を分けて検証する。
