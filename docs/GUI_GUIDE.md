# ローカルGUIの操作ガイド

「加速量の積分・位相設定」で加速長、電圧区間の開始/終了、位相原点をmm指定できる。
空欄は全長/全区間/原点0。区間は全ての掃引ケースの空洞内に収める。
加速長・区間を変えても全蓄積エネルギーとQ0/Gは変わらない。
詳しい規約と鏡映時の意味は [ACCELERATING_CONVENTIONS.md](ACCELERATING_CONVENTIONS.md)。

実装範囲と受入条件は [GUI_IO_PLAN.md](GUI_IO_PLAN.md) を参照。
GUIもCLIと同じFEMを計算する。現時点の対象は真空・閉じた軸対称空洞のm=0 TM。
任意CAD、開放ポート、TE・双極モード、静電・静磁場には対応しない。

## 起動

このREADMEのあるディレクトリで、既存のPython環境を使用する。
初回導入時は `python -m pip install -e '.[plot]'` で描画依存を含める。

```bash
source .venv/bin/activate
superfish-ng gui --workspace out/gui-workspace
```

ブラウザーが開かない場合は、端末に表示された起動URLを同じPCのブラウザーで開く。
`--no-browser` は自動起動を省略する。停止は端末でCtrl+C。
停止すると、そのアプリが実行中の計算も中止する。
通常の計算時にネット接続は不要。インストール時の依存取得は別途必要になる場合がある。

workspaceは履歴の保存先。同じディレクトリを再利用すると過去の履歴を開ける。
計算ごとに新しいサブディレクトリを作り、以前の結果を上書きしない。
同じworkspaceで2個のGUIを同時起動すると拒否される。
初期受入の対象はLinux。ブラウザー・Node・Python本体の同梱配布はしていない。

## 最初の計算

1. 「形状の入力方法」で円筒を選び、半径と長さをmm単位で指定する。
2. モード数、左右の端面条件を確認し、「形状を確認」を押す。
3. 「計算を開始」を押す。計算履歴に新しい項目が追加される。
4. 完了した項目の「結果を開く」を押す。モードを選んで「場を表示」を押す。
5. 「プロジェクトを保存」で編集入力、「計算入力を保存」でCLI用の入力を保存する。

半径は直径の半分。断面図は横軸z・縦軸rで、r=0が回転軸である。
初期値は操作の出発点であり、実機を表したり精度を保証したりする値ではない。

## 輪郭と繰り返し形状

「折れ線」「段差」「円弧」で頂点表を編集する。zは0から右向き、rは常に正。
段差は同じzに異なるrを持つ2頂点で指定する。逆行するzや不正な連続段差は拒否する。
円弧は直前の頂点から終点番号までの短円弧で、半径と(z,r)面での向きを指定する。
弦誤差は曲線の直線近似の設定で、FEMメッシュの細かさとは別。

繰り返し形状は次のように組み立てる。

1. z=0から始まる一部分の輪郭を編集し、「現在の輪郭を組立へ追加」を押す。
2. 他の部分も同様に追加し、各部分の繰り返し数を指定する。
3. 「組立を輪郭へ展開」を押して全体形状を確認する。

例えば左端部・繰り返しセル・右端部の3部分を並べられる。
組立表の「輪郭へ読込」で部分を読み出し、
「選択した部分を現在の輪郭で更新」で変更を反映する。
上下ボタンで順番を変え、端部も通常の部分として編集できる。
セル数は4や7に固定していない。半径が異なる接続は実際の金属段差となる。
組立定義と展開した入力を一緒に保存する。展開後の輪郭を直接編集した場合は、
組立定義との結び付きを解除して、実際に編集した輪郭を計算する。
元の入力に繰り返し情報がなければ、セル構造を自動推定しない。

## 境界、正規化、メッシュ

左右端は金属端板・電気対称・磁気対称から選ぶ。側壁はPEC。
「全空洞へ鏡映」は一端対称・他端PECの場合だけ指定できる。
入力領域の蓄積エネルギーはJで指定する。半領域U=0.5 Jを鏡映すると全領域U=1 Jになる。
出力の場はピークphasorであり、電場と磁場が同時刻に最大になるという意味ではない。

nr/nzは分割の目安。詳細設定では交差分割と境界実長・角近傍の細分を指定できる。
角近傍の「半径」は細分領域の半径で、形状の丸め半径ではない。
円弧形状に角近傍細分は指定できない。条件違反時は入力を保持してエラーを表示する。

## 結果の読み方と保存

履歴で選んだ結果と、左側で編集中の条件は別である。
過去の結果の「この計算の入力を編集」で、その計算条件へ戻せる。
履歴には計算完了・失敗・中止・中断を区別して表示する。
完了とメッシュ収束は別判定で、数値検証していない結果には未検証と表示する。

- モード番号は周波数順であり、物理モード名ではない。
- R/Qのaccelerator/circuitは係数2が異なる。規約欄で式を確認する。
- Epk/Bpkは選択したP1/P2による片側推定。鋭い角のピークは細分しても収束しない場合がある。
- 半径方向プローブのzをmmで指定し、「場を表示」を押す。
- RF表、図、計算出力のJSON・CSV・NPZ・VTKを保存できる。
- 半径方向CSVと設定JSONを一緒に保存すると、z位置・モード・周波数・蓄積エネルギーを残せる。

「保存済みの計算結果を取り込む」で、NGの結果ディレクトリを指定できる。
アプリが動作しているPC上のパスを指定する。既存CLIの出力ディレクトリにも対応する。
入力hashと配列・軸CSVの一致等を確認して履歴へコピーし、元データを変更しない。
これは再計算ではなく、旧形式に完了manifestがなければその事実を記録する。
破損や不足のある出力は成功結果として取り込まない。

## 円筒の解析比較

一定半径・両端PECの円筒では「円筒の解析解と比較」で、実場との重なりから
TM0npを対応付け、周波数・RF量・軸場を別々に比較できる。計算値を解析式で補正しない。
短い円筒ではTM020がTM011より低周波になるため、TM011を常に2番目とは扱わない。
R=75 mmでL=40, 80, 120 mmを比べる場合、4モードを要求すればこの範囲のTM011を含められる。
曖昧な対応や縮退は未検証、粗いメッシュで基準を超えた場合はFAILと表示する。
対称半領域は明示的に全空洞へ鏡映してから比較する。

## 掃引と収束確認

「現在の入力から項目を更新」で、現在の輪郭頂点やRF設定から変更項目を選ぶ。
値は選択項目に表示される単位でカンマ区切りにする。保存される物理量はSI。

- パラメータ掃引: 指定した値ごとに独立計算する。同じ番号を同一モードとして線で結ばない。
- メッシュ収束確認: 例として1, 2, 4の倍率を指定する。nr/nzを増やし、指定された最大辺長を減らす。
- 円弧の形状近似確認: 弦誤差を大きい値から小さい値へ指定する。元の円弧半径は変えない。

形状が同じ細分比較では磁場の重なりでモードを対応付け、周波数・RF量・軸上場を別々に判定する。
近接・縮退等で対応が曖昧な場合はUNVERIFIED。PASSも厳密解への誤差保証ではない。
R/Qが小さい場合の絶対差は診断用で、相対基準を無効にする代替判定にはしない。
条件群の定義は独立のstudy.jsonとして保存・再読込でき、CLIでも実行できる。
各点の入力と場が残るので、比較表の「場を開く」から確認できる。

## バンド同定と分散

両端が空洞中心で、等間隔の同一セルが並ぶ半端部構成だけが対象。
両端を含むセル中心数を指定すると、周期形状・セル間隔・実際の軸場の零交差・振幅を検査する。
同定できた場合だけ位相と分散フィット・残差を表示する。
full-endや非周期形状にこの位相名を付けない。同定不成立でも通常の場表示は利用できる。
これは任意形状の一般的なモード追跡ではない。

## 例題で確認する

`examples/` のJSONを「入力を開く」で読み込む。例題も一般入力と同じ経路を通る。
対象例題・資料ページは [MILESTONE_SEMINAR.md](MILESTONE_SEMINAR.md) を参照。
円筒、段差・円弧付き多セル、half/full端部、対称境界のファイルがある。
例題から寸法やセル数を変更した場合は、新しい形状の計算として収束を確認する。
KEKの実機測定値との一致を保証するものではない。

要素次数はP1（一次、既定）とP2（二次）を選択できる。P2は辺中点の自由度を追加し、
RF積分・保存・再読込でも保持する。形状は直線要素のままで、曲線境界の精度は別に細分する。

## 共通接線で円錐曲線弧をつなぐ

形状編集の「円錐曲線の共通接線を構築」を開き、構築要求または保存した構築結果のJSONを読み込みます。
操作例には `examples/construction/capsule_request.json` を使えます。この例は合成形状です。
要求には元の弧・計算条件・接続する隣接プリミティブの番号・許容差を含めます。形式は[接線構築](TANGENT_CONSTRUCTION.md)を参照。

1. 接点・線分長さ・方向の候補表を確認します。候補は自動選択されません。
2. 順方向の候補を選び、「選択した接線で閉輪郭を検査」を押します。
3. 合格した構築結果を保存し、「検査済み形状と条件を編集画面へ適用」を押します。
4. 通常の入力確認・計算・場表示へ進みます。

適用するまでは現在のプロジェクトを変更しません。適用時は要求内の計算条件も反映します。
要求を編集した場合や候補を変えた場合は再検査が必要です。元の弧を勝手に反転したり延長したりしません。
端点付近・探索未完了は未確認として残し、逆向き・ゼロ長では接続しません。
未確認の診断も構築結果として保存できますが、計算用Caseは生成されません。
保存した構築結果はこの欄から開くと再構築照合されます。通常の「入力を開く」では完成したCase/Projectを開いてください。

版2の区間検査を使う例は `examples/construction/capsule_certified_request.json` です。
この要求を同じ構築欄で開くと、弧の所属・位置区間・生成接点の誤差上界を確認できます。
適用可能な版2結果には最大接点誤差上界を表示します。接線角度は数値検査です。
空になる弧は自動削除しません。版1の構築ファイルも従来どおり読み込めます。

版3の固定直線と弧の例は `examples/construction/capsule_line_arc_request.json` です。
候補表の位置は線分の保持端点と接点を区別し、長さは構築後の線分長を示します。
`allow_extension` で支持直線上の延長可否を明示します。配列の順序が接続方向を指定し、
直線→弧では線分始点、弧→直線では線分終点を保持します。接していない直線の補正や
フィレット生成は行いません。版2と同じ位置誤差上界を表示し、保存後も版3として照合します。

版4の指定半径フィレット例は `examples/construction/corner_fillet_request.json` です。
隣接するPEC線分2本に対し、`radius_m` と延長可否を指定します。第1線分始点と
第2線分終点を保持する小円弧を候補0として確認・選択します。長さ欄は円弧長で、
接点とG1角度は数値検査です。半径が収まらない場合に自動縮小しません。
円/楕円/双曲線弧を含むフィレットには、この要求版を使えません。

版5の弧同士のフィレット例は `examples/construction/two_lobe_fillet_request.json` です。
`radius_m`、`turn_direction`（1=反時計回り、−1=時計回り）、`max_sweep_rad`を指定します。
候補には大回りの円弧も含まれ、上限超過は選択できません。接点誤差上界は元弧とフィレットを
含めて表示します。接線角度は数値検査です。保存後も版5として再構築照合し、完成Caseを明示適用します。
線分と弧のフィレットはこの版の対象外です。


版6の直線と弧のフィレット例は `examples/construction/line_conic_fillet_request.json` です。
版5と同じ半径・方向・最大角に加え、`allow_extension` を必ず真偽値で指定します。
配列順が直線→弧なら線分始点、弧→直線なら線分終点を保持します。
延長を許可しても保持線分を逆向きにしません。弧の有限範囲は延長しません。
例は半径20 mm、反時計回り、延長なし。位置上界・半径・円弧長を同じ候補表で確認し、
選択・保存・再構築・完成Caseの明示適用を行います。

版5/6では、構築候補の下に中心軌跡の特殊ケース診断を表示します。
接触・共有端点・無限パラメータ対等について、確認した事実と指定範囲全体の分類を区別します。
「対象外または未確認」は、この特殊ケース診断の状態です。構築の可否は上の閉輪郭検査結果で確認します。
「中心軌跡の診断を保存」は元の構築を含むJSONを保存し、同じ「構築ファイルを開く」で再検証できます。
診断だけで構築候補の選択や適用を許可しません。要求/候補の変更後は再検査が必要です。
`examples/construction/degenerate_fillet_request.json` は弧端での接触を診断できても
構築は未確認として残る例です。計算用の完成Caseではありません。


曲線形状JSONの `minimum_meridional_radius_m` は読込・構築適用・計算・保存へ保持します。
専用の編集欄はありません。例 `examples/construction/radius_constrained_fillet_request.json` は
半径20 mmのフィレットを含むPEC壁に19 mm以上を要求します。詳細は[半径制約](MERIDIONAL_RADIUS.md)。

## モード群の集合継承方式

「モード対応と追跡履歴」で「モード群をID集合として継続する」を有効にすると、
集合継承の方式を選べる。初期値は合流・分裂（1対多・多対1）。
多対多を含む方式は、両側に多次元群がある場合の保守的な和集合継承を許可する。
集合内の個別IDは未確定のまま。詳細は[追跡仕様](MODE_TRACKING.md)。
保存対応/履歴を開くと方式とリンク閾値を復元し、次の履歴比較へ反映する。
無効化すると方式とリンク閾値は比較要求に含まれない。
Studyの共通controlsにも同じ選択を使う。明示した段階別JSONはその内容が優先される。

## 同じ領域の独立再メッシュ比較

「モード対応と追跡履歴」の比較写像で「同じ直線境界の領域（異なるメッシュ）」を選ぶ。
別々に三角形分割した結果を、頂点対応の入力なしで比較できる。折返し境界とP1/P2場に対応。
領域全体の直線境界とPEC/axisタグが一致する必要がある。異なる形状や二次曲線幾何は拒否する。
保存した対応/履歴を開くと写像と標本次数を復元し、履歴継続にも使う。
標本次数を上げて結果を確認する。対応PASSだけでRF量の収束を判断しない。

## アフィン変形の独立再メッシュ比較

比較写像で「軸を保つアフィン変形（異なるメッシュ）」を選び、半径倍率a、軸方向倍率c、
軸方向せん断bを入力する。旧結果から新結果への変換はr'=a r、z'=b r+c z。
a,cは正数。保存文書から写像と3係数を復元する。
逆方向へ比較を続ける場合は、比較結果の選択を逆にし、「入力した変換を逆変換にする」を押す。
この操作は入力欄を1/a、1/c、-b/(a*c)に変える。保存済み履歴は比較・継続時に再検証される。
誤った写像は境界不一致で拒否され、最後の確認済み結果を保持する。
他の写像を選ぶとアフィン係数は送られない。曲線二次幾何と非アフィン変形は対象外。

## 比較用メッシュによる区分アフィン変形

比較写像で「比較用メッシュによる局所変形」を選び、旧・新の完全なメッシュJSONを
2要素配列として入力する。両者は共通の頂点番号・三角形接続を持ち、それぞれの物理領域を覆う。
実FEMメッシュとは別に指定できる。入力形式と制限は[追跡仕様](MODE_TRACKING.md)を参照。
保存文書を開くと比較メッシュ2件を復元する。逆方向へ比較する場合は結果を逆に選び、
「旧・新の比較メッシュを入れ替える」を押す。入れ替えは入力欄だけを更新し、
メッシュの完全被覆・向き・境界は比較/履歴継続時に検証する。
不正な配列は部分更新せず拒否し、比較失敗でも確認済み履歴は保持する。
他の写像を選ぶと比較メッシュ宣言は送られない。

## 同じ二次曲線境界の比較

比較写像で「同じ二次曲線境界の領域（異なるメッシュ）」を選択する。
同じ曲線定義・パラメータ付けと同じ二次近似境界が必要。固定曲線を保つ細分を比較できる。
解析曲線が同じでも、再投影によって二次近似境界が変わった結果は拒否する。
保存対応/履歴から写像を復元でき、比較診断に共通区間数・係数距離・丸め幅等を表示する。
比較や履歴継続が失敗しても、最後に確認した履歴を保持する。保存には境界照合の証拠も含む。
標本次数を変えて対応を確認し、追跡PASSをRF収束と扱わない。
