# 追跡付き適応細分のGUI

「同じモードを追跡してメッシュを細分する」から、既存の適応API・JobManagerを操作する。
対象は固定した直線要素領域の真空・軸接続m=0 TM（P1/P2）。物理条件・幾何・正規化を
水準間で固定する。二次曲線幾何の局所細分は未対応として拒否する。
[計算仕様](ADAPTIVE_REFINEMENT.md)と[JobManager契約](ADAPTIVE_REFINEMENT_JOBS.md)を変更しない。

## 入力と実行

1. 上の形状・メッシュ・物理設定を編集する。
2. 確認方式、残差指標の選択割合、水準/要素数/最小角制約、f/RQ/Gの相対変化基準、
   追跡の四閾値、初期順位ごとの全IDと対象IDを指定する。
3. 「現在の形状と上の条件から入力を作成」を押し、JSONを確認する。
   JSON入力欄は文字列のままサーバーへ送り、入れ子を含む重複キー・未知指定を厳密に拒否する。
4. 必要なら「今回追加する水準の上限」を指定し、「適応計算を開始」を押す。
5. 計算一覧の「結果を開く」で、保存場から全再構築した結果を表示する。

版2ではnested_affineとuniform_two_stepsを明示する。局所候補の後、全域細分を最低2回行う。
版1を選択した場合はsame_domainと標本次数を使い、全域確認なしであることを表示する。
他のモード追跡画面の写像や設定は流用しない。版1の既存保存文書を自動昇格しない。
新しい入力の初期メッシュはnull（Caseから生成）。明示メッシュを使う場合はJSONの
initial_meshへ指定できる。再読込・再開時は明示メッシュを含む保存要求全体を維持する。
初期ID欄が空ならmode-1、mode-2…を生成する。IDは解析モード名の推定ではない。

初期値のf=1e-4、RQ/G=0.005は相対的な細分差の条件で、物理誤差の保証ではない。
厳しい条件やP1では、多くの水準・要素を要したり、資源制約で停止したりする。
Caseのメッシュ制約が厳しければそちらを使用する。上限を自動で増やさない。

## 結果・保存・再開

ジョブがcompleteでも数値判定はTARGETS_MET、PAUSED、UNVERIFIED、各種上限停止などに分かれる。
一覧と結果パネルに両者を表示する。各水準の局所/全域確認、要素数、自由度、対応状態、
対象順位、f、加速器規約R/Q=V²/(ωU)、Gを表にする。
直近2区間の三量の変化・許容値・個別判定も別表に表示する。
全域確認が1回しかなければ、差がすべて条件内でも版2の達成にはしない。
未確認の対象量は「評価不可」。表面ピークは未評価、物理誤差上界はなしと明示する。

保存ボタンはサーバーが再検証して返したJSONをそのままダウンロードする。
「チェックポイントを開いて再検証」でページを開き直した後も復元できる。
元のnative保存先が必要であり、ダウンロードしたJSONだけで場データを移送する機能ではない。
改変文書・元ファイル変更は拒否し、最後に再検証できた表示を保持する。
「確認済みの続きから再開」は保存要求を使い、入力欄への新しい編集は反映しない。
今回追加する水準上限だけを別に指定できる。新規ジョブへ追加水準のみを計算し、先祖水準は保持する。
終端判定からの再開はできない。

計算一覧から実行中ジョブを中止できる。中止・失敗後に途中保存がある場合は、
そのジョブのexecution/checkpoint-NNN.jsonをファイル選択から開き、再検証後に再開する。
書込みが完了していないファイルは拒否されるため、その場合は前の完成したチェックポイントを使う。
中止されたジョブを完了結果として開くことはできない。

「表示中の最終水準の対象場・RFを開く」は、再検証した最終水準のmode_indexに従う。
順位1を暗黙に選ばない。対象量が未確認ならボタンを無効にする。
途中/上限停止でも確認済みの離散場は観察できるが、表示によって精度達成にはならない。

## 検証手順

```bash
OPENBLAS_NUM_THREADS=1 python -m unittest discover -s tests -p test_gui_adaptive_refinement.py -v
superfish-ng gui --workspace out/gui-refinement-new --no-browser
node scripts/verify_gui_adaptive_refinement.mjs --url '表示された起動URL' --out out/browser-refinement-new --request examples/adaptive_refinement/pillbox_confirmed.json --workspace out/gui-refinement-new
```

4件の通信検査は実workerで版2確認途中の再開、版1保存再検証、数値未確認/中止状態の分離、
厳密な入力、改変文書/元ファイルと異種ジョブの拒否を確認する。
ブラウザー検査は実クリック/入力/ダウンロード/再読込、両版、個別f/RQ/G表示、対象順位2の場表示、
全域確認途中の再開、未確認/上限停止、生きたジョブの中止と保存からの再開を確認する。
ローカルHTTP以外へのページ通信を拒否し、検知した外部リクエストとソース変更を失敗として記録する。

一般形状の精度/効率受入、曲線局所細分、表面量停止は未完。N04全体の完了ではない。
