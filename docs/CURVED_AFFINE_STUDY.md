## 受入条件と入力

従来のStudy版1は、明示メッシュや曲線細分履歴を持つ形状掃引を一律に拒否していた。
番号の意味を保持できる[宣言アフィン変換](CURVED_PROJECT_TRANSFORM.md)と
[局所分割の固定](FROZEN_CURVED_REFINEMENT.md)を用いて、この用途を明示する版2を追加した。
受入条件は、独立した各点・固定した親子関係・RF座標方針、厳密な入力と点ごとの幾何検査、
実FEM/保存再生、各点間の実際の相対写像、解析順位交差、区間二分、CLI/GUIである。

新しい `study_version: 2` は `kind: "curved_affine_sweep"` 専用。
版1の各kindは変更せず、版2のフィールドを混入させると拒否する。
携帯可能な合成例は [examples/curved_affine_study.json](../examples/curved_affine_study.json)。
元メッシュと二つのmarked段階の分割宣言を含む。測定された空洞ではない。

| フィールド | 契約 |
|---|---|
| `project` | 組立sectionsのないnative curved_contour、geometry_order=2のTM Project |
| `parameter` | 空白だけではない変数名 |
| `parameter_unit` | `1`（無次元）または `m`。値と多項式係数はその単位で指定 |
| `values` | 二つ以上の有限な数。通常掃引の順序は自由で、同じ値へ戻ることも可能 |
| `affine_coefficients` | radial_scale / axial_scale / axial_shearの三配列。定数項から次数順 |
| `rf_coordinates` | `fixed` または `axial` の明示指定 |

変形は `(r,z) → (a(x)r, b(x)r+c(x)z)`。
各係数配列は空でない有限数列で、少なくとも一つの法則に非零の高次項が必要。
a/cは評価した各条件で正、bは有限とする。
多項式のk次係数の単位は1/(parameter_unit)^k。GUIでもmはSIのmのまま入力する。
巨大な整数・bool・非有限値は入力エラーとして拒否する。
法則の評価には既存曲線tuneの `trial_map` を再使用し、新しい多項式評価式を作らない。

RF座標のfixed/axial、暗黙位相原点、曲線の弦誤差予算・固定元メッシュ・品質/要素予算は
[Project変形](CURVED_PROJECT_TRANSFORM.md)に従う。
TEは加速座標を持たないため、この版2では専用の座標契約が必要と明示して拒否する。
既存のTE Studyや版1の範囲を変更しない。
正のa/cだけでは有効な空洞とは限らず、軸端のz範囲、半径、曲率等も各点で再検査する。
形状全区間の妥当性や、その間の連続物理枝を保証しない。

未固定のmarked履歴も従来のprefix照合を通る変形なら使える。
幾何に応じた分割選択が変わる場合は接続不一致で拒否する。
先に固定した履歴では分割辺・遷移対角線を再利用し、同じ参照制限を再構築する。
通常Studyは全指定点を事前検査してから出力を作成する。

```sh
OPENBLAS_NUM_THREADS=1 .venv/bin/python -m superfish_ng study examples/curved_affine_study.json --out out/new-affine-study
```

通常Studyの結果は独立スペクトルである。細分比較を行わず、comparisonsは空、
numerical_statusはUNVERIFIED、mode_trackingは未実施を保持する。
既存のCLI終了0は指定点の計算完了を意味し、収束やモード対応の合格ではない。

## 追跡と区間二分

保存Studyの `track-study-modes`、`execute-tracked-study` の逐次計算/再開、
`execute-adaptive-study` の区間二分/再開も同じ版2 Studyを受け付ける。
外側の追跡要求・保存文書の版は変えない。
元の各区間に対するstep_controlsは `mapping: "affine_remesh"` と閾値を指定し、
`affine_map` は含めない。手動の行列を同時に指定すると拒否する。

実際に比較する前後の値x₀/x₁から
`A(x₁) @ inverse(A(x₀))` を導出し、実保存場の比較要求へ含める。
元要求は行列なしのまま保存し、履歴には導出した実行列を保存する。
完全replayは法則・条件値・元Projectと全保存場から再構築する。
不正な未訪問区間のcontrolsも事前に拒否する。

区間二分では値の列を厳密単調とし、既存の深さ・試行数・最小幅上限を維持する。
閾値は元の対象区間から継承するが、写像は実際の比較点から毎回求める。
例えば1→1.5を二分して1→1.25を比較する場合、軸倍率は1.25である。
1.5を再利用して中間点に誤った対応を与えない。
拒否された比較、計算済み点、未達の終端、保存再開の出所検査は従来どおり保持する。
UNVERIFIEDを収束や個別IDの回復として扱わない。

GUIは「元メッシュを保つ曲線アフィン掃引」を選び、変数名/単位/三法則/RF方針を入力する。
保存と実行の前に全指定点を検査し、非同期の検査中に入力が変われば旧応答を破棄する。
定義を開くと全設定と固定分割を復元する。
完了Studyの追跡と逐次/適応要求の準備では、宣言から導出するcontrolsを作成する。
明示step_controlsのJSONを入力する場合も同じ規約に従う。
