# 同じ真空領域のHφ部分空間対応

[計画](HPHI_SAME_DOMAIN_TRACKING_PLAN.md)のAPIを固定629sourceから主ツリーへ統合し、以下の範囲で限定受入。
`track_hphi_modes(previous, current, request)` は、外周・全PEC穴が厳密に一致する二つの元Hφ解を比較する。
正半径のq=rHφと軸接続のu=Hφ/rをそれぞれ扱い、異なる物理形式の間を暗黙に変換しない。

要求は `HphiTrackingRequest`、strict JSON形式は `superfish_ng_hphi_tracking_request` の版1。
前後の比較メッシュとP1/P2次数、最低正スペクトルの追跡数、前の個別IDまたは全順位を分割したID集合、全controlsを保存する。
各元解には追跡帯域より上に少なくとも一つの計算済みguardモードが必要で、不足する要求は実行前に拒否する。
比較メッシュは同一領域・元より多い三角形・小さい最大辺長・元以上の次数を要求する。

元の最低正スペクトルと規格化・係数を完全に再検証し、元要素上の全3D E/H体積内積をそれぞれ計算する。
両元解を明示比較空間へ射影し、シフト逆行列残差から得た有限スペクトル区間と周波数間隔で群を作る。
群が追跡帯域からguardへ及ぶ場合、帯域または最初のguardの射影・有限上端が未検証の場合はUNVERIFIEDとなる。

E/Hを別々に規格化した物理Gramから全方向の主内積を計算し、最小主内積と他候補への割当余裕で対応する。
既定の最小主内積は.9、割当余裕は.1、周波数の相対群間隔は.001、最大射影誤差は.01。
E/Hの順位集合・ID集合の対応が一致し、個別モードでは両場で必要な元係数の符号も一致することを要求する。
指定余裕が極小でも、共通積分の演算規模に応じた数値余裕を割当条件へ加え、実際に使った値を結果へ記録する。

多次元の対応はSUBSPACEとしてID集合を保持し、元の各IDを現在の各基底へ割り当てない。
周波数が後で分離しても、過去のID集合だけから元の個別IDを復元しない。
どれかの全体検査が未達なら現在の個別IDを全てnullとし、対応候補・両場の主内積・理由を診断として保持する。
元の固有周波数・係数・RF量は変更しない。

PASSは指定された二つの有限FEM部分空間の数値対応である。
有限比較区間は保証された区間演算ではなく、連続問題の誤差上界・連続した形状変更の同一性・表面ピーク精度を証明しない。
保存/worker/CLI/GUIと履歴連鎖・形状写像は別工程で扱う。

## 独立した検証

追加4unitは22.137秒でPASS。要求の完全分割、位相反転、元係数不変、ID集合の保持、guard・曖昧さ・改変解の拒否を確認した。
48FEM/nativeと36比較は148.283秒でPASS。軸あり/なし・0/1/2穴・二尺度・P1→P1/P2とP2→P2を含む。
独立な物理座標の多項式と微分、別の画素三角形積分からE/Hを再構成し、物理Gram最大差3.243e-15、主内積差2.554e-15、相似差1.219e-13を得た。
製品判定は32PASS/4UNVERIFIEDで、粗い結果を一律に合格へ変更していない。元240nativeファイルは不変。

解析的な二重縮退と順位逆転は別の12FEM/native・正逆12比較で確認した（58.292秒）。
閉同軸のTEMと半径TMが縮退する長さを使い、P1/P2・二尺度で独立メッシュのTEM順位が1→2へ実際に逆転した。
軸接続円筒のTM011/TM020についてもP2・二尺度で確認した。
解析H場の部分空間との最小主内積は.99以上で、正逆とも二次元ID集合を保ち、個別IDは未確定のまま。元60nativeファイルは不変。
