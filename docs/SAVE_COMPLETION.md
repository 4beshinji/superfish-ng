# O01: 保存結果の完了公開

2026-09-08仕様。直接save_run、CLI、Jobのsolutionに同じ完了契約を適用する。
数値・case hash・場形式は変更しない。物理不変量は保存前後の場・周波数・RF量の一致。
独立した操作不変量は「完了前の読込拒否」「既存出力を一切置換しない」。

出力ディレクトリをmkdirで排他的に確保し、save_protocol.json（version=1）を作る。
予約ディレクトリ内の隠れた一時ディレクトリへ全出力を作成する。
全ファイルを非置換のhard linkで最終名へ移し、全必須ファイルのSHA-256を持つ
save_complete.jsonを最後に非置換で公開する。これが読取APIに対する原子的な完了点。
ディレクトリ名や個別ファイルが早く見えること自体を完了とは扱わない。

通常の例外では一時領域だけを掃除し、予約ディレクトリと不完全な出力を保持する。
強制終了時には一時領域も残り得る。完了マーカーのない新形式は常に読込拒否し、
既存出力として同じパスへの再保存も拒否する。再実行には新しいパスを使う。
results.jsonにもsave_protocol_version=1を保存し、protocolファイルだけの欠落を検出する。

read_solutionは新形式で完了マーカー・版・全必須ファイル集合・各hashを検査する。
材料/領域付きcase、外部mesh.json、全モードのCSV/VTKを対象とする。
必須集合はcaseと結果の契約から導出し、マーカーに書いていない欠落を見逃さない。
symlinkと範囲外パスを受理しない。保存後に作った図など追加ファイルは対象外。

旧保存結果はprotocolとresults内の新フィールドがないときに限り従来検査で読む。
「旧結果に完了記録があった」とは表示しない。マーカーは電子署名でなく、全証拠を
同時に書き換える攻撃や旧出力に見せかける改ざんの真正性保証ではない。
Jobへの取込は外部meshと新完了ファイルもコピーし、コピー後に再検査する。

対象は同一ローカルファイルシステムでのプロセス失敗・強制終了・同名競合。
hard linkが使えないファイルシステムでは保存を失敗させる。電源断に対する永続性や
ネットワークファイルシステム・他OSの挙動は本受入で保証しない。

受入: 各出力段階と公開段階の故障注入、実プロセスの強制終了、同名保存競合、
完了ファイル欠落/改変/パス不正、外部mesh付き取込、旧結果再読込、通常CLI/Job回帰。
標準unittest/validateと直前の周波数/RF差を確認して受入記録を追記する。
